# ADR 0008：移动端分发的候选手机自动调度

当前仅提供全局系统管理员管理入口，不维护学校或分发工作空间成员角色。

状态：现行。日期：2026-11-04。本文替代历史手机执行规范中“平台校验 UI 规则”“条件变化不自动换机”“等待原手机静止才能继续”的规则。

## 业务边界

平台保存正文、目标、业务间隔及授权候选范围。手机负责本地执行。任务、目标投递、设备尝试分层保存；候选内自动换机不改变正文或业务意图，不要求重新确认。平台不知道手机实际登录的企业微信账号；群名与设备备注不构成账号或真实群认证。

新任务预览明确展示唯一业务群名和全部授权候选；所选手机为首选。确认时冻结有效候选的绑定、定位、凭据代次及使用范围快照。新增绑定、变更定位或更换凭据不自动扩大既有授权；不再匹配的候选被跳过，需改变授权范围时重新确认。

## 调度与反馈

平台按连接、设备占用、凭据及业务额度选择候选；锁屏、权限与本地适配由设备在本次尝试处理。平台不查询手机托管意愿，设备不可执行时按本次未调用回报。平台在已确认范围内选择下一可用手机，全部暂不可用则保持任务已受理，在最多三轮候选遍历内定期重评。三轮包含首次；每轮至少保留 5 分钟，候选遍历结束不能按 5 秒扫描周期提前扣轮。只有一台手机且一直无反馈时，三轮约 15 分钟（另加固定扫描及领取延迟）。每个目标独立持久计数，第三轮耗尽后报告下发失败并停止自动下发，重启或手机上线不重置预算。在线信息可能过期，实际下发后的拒绝、失败、超时及反馈同样参与协调。失败候选有有界退避，避免高速循环；健康的现有分配不会因首选恢复而来回换机。

当前手机明确离线且还有未遍历的授权候选，或明确执行失败时，直接切换到冻结候选顺序中的下一可用手机；已接收后 5 分钟没有最终结果时同样换机。已领取任务不再套用新分配的 30 秒心跳新鲜度、暂停或忙碌检查；只有一台手机时，即使控制连接中断，仍须等待该次结果期限，不能提前进入下一轮。接收回执首次记录时间使用数据库时钟，重复回执/进度不续期；包生成后 60 秒无接收确认且无最终结果，记录接收确认超时并换机。候选均不可用时保持任务受理，本轮候选耗尽后持久保存轮次开始时间及截止重试时间，至少满 5 分钟后才能扣轮并重新遍历；扫描、重启、重复回执不能重置该期限。未签发包的分配记录候选不可用或交付资格原因并继续候选；业务间隔未到不计时。耗尽不意味着历史 unknown 确定未发送，迟到成功仍按原尝试入账。再次发送须复制为新任务并重新确认。

新执行协议仅保留 v10 直接交付：平台为选定尝试一次生成完整签名 `durable_execution/1`，与额度、持久出站记录原子提交，再经认证 WSS 控制帧的 `executions` 发送 `mobile_execution_delivery/1`（内含完整 `task_delivery/1`）。正常发送不再提供任务提示、任务领取或执行许可申请接口。手机验签落盘后直接本地执行，不联网复核依赖或续租；接收确认写入本地 outbox，通过控制脉冲的 `execution_receipts` 异步补报，最终结果独立补报。重连复用原包及单次能力，不重新签发。无发送检查通过独立 inspection-executions 接口授予 max_calls=0 能力。

一个后台作业每 5 秒扫描数据库，完成结果入账与分配推进，不为每任务保留等待线程或数据库连接。新结果持久化后标记待扫描；多实例用数据库锁协调，重启不重置期限。

不同目标独立调度，遵守已确认的业务间隔，不等待前群结果或原手机结算。结算只释放对应物理资源，不推进新模式任务的全局群游标。成功以结果事实判断，领取、收件和准备均不代表已发送。

平台不提供手机专用群名、搜索词覆盖或别名。绑定仅确定候选手机；预览、使用范围和执行目标都取目标群的唯一业务群名。群名变化会使未签发的旧计划失效；若原冻结范围已无合法候选，则结束该目标调度，不永久等待手机。其他合法目标与新任务继续正常受理。已签发执行包保留原群名、授权与摘要，恢复和结果补报沿用原尝试，不静默改名重签。

## 历史与实现

`dispatch_mode=candidate_pool` 用于新预览确认的任务。候选范围单独不可变保存，分配、失败退避和调度状态单独记录；每次换机新建不可变计划及尝试，保留自动/手动来源和原确认授权人。

历史任务继续使用 `legacy_sequence`，不从当前绑定推断历史授权，也不重写已有摘要、凭据或恢复身份；需要候选池时复制意图并重新确认。未获许可的旧尝试在新模式中失效后不能复活。旧协议接口全部移除；原设备既有加密结果与 calling 事实归档核对，新协议不恢复旧点击。

调度工作器位于现有 API 进程，独立于使用范围投影、诊断及等待观测；单项事务隔离失败，使用数据库协调支持多实例，不新增部署服务。平台使用隔离数据库及模拟执行协议验证自动换机，不要求真实测试手机作为平台业务门禁。Android 本地执行适配仍由独立客户端负责。

## 验收

必须覆盖 A 离线调度 B、A 领取后调用前失联、失效尝试迟到获许可被拒、授予与换机竞争、unknown 到期自动切机、全部离线仍受理、不可越出候选范围、所有候选使用同一业务群名、旧覆盖数据不得进入执行包、反馈幂等、5 秒扫描与跨目标推进。Rust 与 TypeScript 以共享 fixture 验证调度状态和分配历史。

## 来源路由自动执行授权（2026-11-09）

消息接收后的处理属于 WeKeeper。本项目接受系统管理员启用自动执行；启用/恢复操作明确确认此业务授权。每条内容据此冻结完整配置修订、正文、目标及当前合法手机候选，以 `authorization_kind=source_route` 区别于逐条人工确认，以 `source-routing` 记录真实执行身份和授权人。系统不调用人工确认 HTTP 接口，不伪造管理员点击。手动任务的预览与确认要求继续生效。

自动任务进入现有候选调度、额度和单次执行许可流程。新增目标或绑定不扩大既有任务；后续可控提交核对暂停、撤权、退役及冻结候选当前合法性。凭据删除不取消已经生成的授权任务；单位及目标控制继续生效。已签发手机执行包直接本地执行，不能追加联网审批。接收配置缺失、关闭或全部目标资源不可用时，该消息结束为未下发；修复配置仅作用于后续新消息，不自动重放旧消息。手机平台暂停不冻结已受理任务的三轮预算；预算耗尽后结束为下发失败，恢复开关不重置预算，再次发送须创建并确认新任务。业务执行不依赖研发验收、发行或其他项目状态。

## 本机意愿与平台边界（2026-11-18）

平台不具有本机托管状态模型，不查询或操作本人同意、暂停、恢复和撤回。环境观测仅限带 ID 与时间的交互、锁屏、权限和应用登录闭集事实；没有观测也可签发。`not_called/device_unavailable` 是当次执行的未调用结果，按原凭据和摘要幂等结算、释放占用并选择下一授权候选，仍遵守三轮和每轮至少五分钟的预算。控制帧版本为 2，指定执行取消不改变手机全局意愿。
