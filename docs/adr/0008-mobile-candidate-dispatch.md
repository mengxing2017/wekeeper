# ADR 0008：移动端分发的候选手机自动调度

状态：现行。日期：2026-11-04。本文替代历史手机执行规范中“平台校验 UI 规则”“条件变化不自动换机”“等待原手机静止才能继续”的规则。

## 业务边界

平台保存学校、正文、目标、业务间隔及授权候选范围。手机负责本地执行。任务、目标投递、设备尝试分层保存；候选内自动换机不改变正文或业务意图，不要求重新确认。平台不知道手机实际登录的企业微信账号；群名与设备备注不构成账号或真实群认证。

新任务预览明确展示唯一业务群名和全部授权候选；所选手机为首选。确认时冻结有效候选的绑定、定位、凭据代次及使用范围快照。新增绑定、变更定位或更换凭据不自动扩大既有授权；不再匹配的候选被跳过，需改变授权范围时重新确认。

## 调度与反馈

离线、锁屏、权限、本地适配、忙碌、未同意托管、配额冷却等仅使该候选本轮不可选。平台在已确认范围内选择下一可用手机，全部暂不可用则保持任务已受理，在最多三轮候选遍历内定期重评。三轮包含首次；每个目标独立持久计数，第三轮耗尽后报告下发失败并停止自动下发，重启或手机上线不重置预算。在线信息可能过期，实际下发后的拒绝、失败、超时及反馈同样参与协调。失败候选有有界退避，避免高速循环；健康的现有分配不会因首选恢复而来回换机。

当前手机离线或明确失败时，直接切换到冻结候选顺序中的下一可用手机；已接收后 5 分钟没有最终结果时同样换机。接收回执首次记录时间使用数据库时钟，重复回执/进度不续期；无回执时以授予时间加 5 分钟兜底。候选均不可用时保持任务受理，在三轮上限内后续扫描重新评估。未签发包的可下发分配超过五分钟未领取也切换候选；业务间隔未到不计时。耗尽不意味着历史 unknown 确定未发送，迟到成功仍按原尝试入账。再次发送须复制为新任务并重新确认。

新执行协议仅保留 v10：`task-deliveries` 由平台自行选择任务，在交付前一次授予有界能力，返回包含签名执行包的 `task_delivery/1`。手机不提交候选尝试列表，持久接收后直接本地执行，无后续执行申请、依赖联网复核、准备/调用许可或续租。显示收件、旧申请恢复、回执及历史结果补报均不成为新任务执行的前置条件。`plan_dependency_changed` 只用于平台交付前结束未签发的失效尝试，不能撤销或阻塞已经交付的执行包；失效后继续选择后续合法任务，仅失效项时返回可重试的队列已刷新状态。unknown 不阻止同目标自动换机，原机物理占用仅隔离原机；平台作废分配不能撤销离线已发能力，因此可能产生跨手机重复，单次消费保证仅在各能力内成立。迟到成功结束目标并尽力取消尚未执行的后继，迟到失败只记录原尝试。

一个后台作业每 5 秒扫描数据库，完成结果入账与分配推进，不为每任务保留等待线程或数据库连接。新结果持久化后标记待扫描；多实例用数据库锁协调，重启不重置期限。

不同目标独立调度，遵守已确认的业务间隔，不等待前群结果或原手机结算。结算只释放对应物理资源，不推进新模式任务的全局群游标。成功以结果事实判断，领取、收件和准备均不代表已发送。

平台不提供手机专用群名、搜索词覆盖或别名。绑定仅确定候选手机；预览、使用范围和执行目标都取目标群的唯一业务群名。群名变化会使未签发的旧计划失效；若原冻结范围已无合法候选，则结束该目标调度，不永久等待手机。其他合法目标与新任务继续正常受理。已签发执行包保留原群名、授权与摘要，恢复和结果补报沿用原尝试，不静默改名重签。

## 历史与实现

`dispatch_mode=candidate_pool` 用于新预览确认的任务。候选范围单独不可变保存，分配、失败退避和调度状态单独记录；每次换机新建不可变计划及尝试，保留自动/手动来源和原确认授权人。

历史任务继续使用 `legacy_sequence`，不从当前绑定推断历史授权，也不重写已有摘要、凭据或恢复身份；需要候选池时复制意图并重新确认。未获许可的旧尝试在新模式中失效后不能复活。旧协议接口全部移除；原设备既有加密结果与 calling 事实归档核对，新协议不恢复旧点击。

调度工作器位于现有 API 进程，独立于使用范围投影、诊断及等待观测；单项事务隔离失败，使用数据库协调支持多实例，不新增部署服务。平台使用隔离数据库及模拟执行协议验证自动换机，不要求真实测试手机作为平台业务门禁。Android 本地执行适配仍由独立客户端负责。

## 验收

必须覆盖 A 离线调度 B、A 领取后调用前失联、失效尝试迟到获许可被拒、授予与换机竞争、unknown 到期自动切机、全部离线仍受理、不可越出候选范围、所有候选使用同一业务群名、旧覆盖数据不得进入执行包、反馈幂等、5 秒扫描与跨目标推进。Rust 与 TypeScript 以共享 fixture 验证调度状态和分配历史。
