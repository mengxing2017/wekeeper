# ADR 0008：移动端分发的候选手机自动调度

状态：现行。日期：2026-11-04。本文替代历史手机执行规范中“平台校验 UI 规则”“条件变化不自动换机”“等待原手机静止才能继续”的规则。

## 业务边界

平台保存学校、正文、目标、业务间隔及授权候选范围。手机负责本地执行。任务、目标投递、设备尝试分层保存；候选内自动换机不改变正文或业务意图，不要求重新确认。平台不知道手机实际登录的企业微信账号；群名与设备备注不构成账号或真实群认证。

新任务预览明确展示全部授权候选及各自搜索名；所选手机为首选。确认时冻结有效候选的绑定、定位、凭据代次及使用范围快照。新增绑定、变更定位或更换凭据不自动扩大既有授权；不再匹配的候选被跳过，需改变授权范围时重新确认。

## 调度与反馈

离线、锁屏、权限、本地适配、忙碌、未同意托管、配额冷却等仅使该候选本轮不可选。平台在已确认范围内选择下一可用手机，全部暂不可用则保持任务已受理并定期重评。在线信息可能过期，实际下发后的拒绝、失败、超时及反馈同样参与协调。失败候选有有界退避，避免高速循环；健康的现有分配不会因首选恢复而来回换机。

未签发发送许可的尝试失联或超时，平台原子关闭该尝试并禁止迟到 prepare/invoke，再创建新尝试。该事务与许可签发共用数据库协调锁，只有一方可生效。旧手机的物理租约与非静止状态保留，只隔离该手机，不阻止另一台手机推进业务。

已签发许可后失联不能推断未发送。该目标保留 unknown 核对，其他目标独立继续调度。人工确认未发送须等待原许可窗口结束；后续尝试仍在原授权候选范围内。人工核对与旧设备迟到的认证结果发生冲突时，原尝试重新进入核对，保留历史结论和反馈；后继尝试不得覆盖原身份或继续取得新许可。历史尝试可独立核对，核对确认已发送后结束该目标，不能再重发。

未知投递的逻辑风险不扩大为无关目标或学校的逻辑风险，实际调用仍受正常时段、间隔和额度约束。物理上未恢复的手机仍不能并发操作自身界面。

不同目标独立调度，遵守已确认的业务间隔，不等待前群结果或原手机结算。结算只释放对应物理资源，不推进新模式任务的全局群游标。成功以结果事实判断，领取、收件和准备均不代表已发送。

## 历史与实现

`dispatch_mode=candidate_pool` 用于新预览确认的任务。候选范围单独不可变保存，分配、失败退避和调度状态单独记录；每次换机新建不可变计划及尝试，保留自动/手动来源和原确认授权人。

历史任务继续使用 `legacy_sequence`，不从当前绑定推断历史授权，也不重写已有摘要、凭据或恢复身份；需要候选池时复制意图并重新确认。未获许可的旧尝试在新模式中失效后不能复活。原设备结算和结果回收保持可用。

调度工作器位于现有 API 进程，独立于使用范围投影、诊断及等待观测；单项事务隔离失败，使用数据库协调支持多实例，不新增部署服务。平台使用隔离数据库及模拟执行协议验证自动换机，不要求真实测试手机作为平台业务门禁。Android 本地执行适配仍由独立客户端负责。

## 验收

必须覆盖 A 离线调度 B、A 领取后调用前失联、失效尝试迟到获许可被拒、invoke 与换机竞争、调用后 unknown 只隔离目标、全部离线仍受理、不可越出候选范围、不同搜索名、反馈幂等、退避及跨目标推进。Rust 与 TypeScript 以共享 fixture 验证调度状态和分配历史。
