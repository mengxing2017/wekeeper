# ADR 0005：服务端手机执行通道

日期：2026-10-24。继承 ADR 0002 的学校隔离、人工确认、单次调用与 unknown 核对语义。

## 决策

手机是外部执行器，主动通过专用 HTTPS Bearer 协议领取结构化任务。服务端不连接 ADB，不执行手机脚本，不提供坐标、Shell、Hook、注入或私有协议入口。首次交付 backend 接口和不部署的 TypeScript HTTP client；2026-10-26 按后续需求补齐工作台设备/账号管理与学校手机任务页面，入口见手机执行运行手册。仍不包含 Android 执行端开发。

设备、实际发送账号、规范化群、后台运营人员分别建模。平台管理员不能越过学校成员授权。普通微信群使用经人工核验的稳定内部身份；企业微信群要求映射已有官方身份。禁止以昵称自动合并身份或通过删除资源清空历史。发送账号的负责运营人员必须具备本校 admin；同一真实账号在所有学校、设备上使用同一记录。

一任务逐群冻结正文。文本需学校 admin 确认，帖子需 operator/admin 确认；确认必须携带当次 preview_digest，并人工确认实质差异与范围。模板与帖子 revision、群与账号身份和绑定快照在发送资格事务再次验证。NFC、换行统一、首尾裁剪后计算跨通道正文摘要；不改写旧内容/hash，不把“摘要不同”当作实质差异的证明。

## 并发与证据

v1 使用 PostgreSQL 全局事务 advisory guard `78234610241` 协调手机、官方与旧人工分享写事务。这是有意选择的保守吞吐实现：先守住跨学校账号/正文约束，后续扩容再迁移到排序的 scope guards。事务不持有跨网络请求。数据库时间使用 clock_timestamp，避免等待事务锁期间的陈旧事务起始时间缩短冷却。

准备 lease 为 120 秒；可在有效 fence 下续租。准备不占发送额度。permit 原子持久化唯一 invocation、token hash、60 秒窗口和 usage；从此不能自动重新排队。未知永久占用相应账号、群、正文，不能因跨天释放。UI 回报只有“观察到发送气泡”，不生成 official_status、delivered 或 read；点击时间不可信，冷却从服务端接收观察时间计算。超窗或身份不一致回报保持 unknown。

不保存可回放的明文 permit/credential/pairing secret，不引入回放加密密钥。首次响应之外仅保存摘要，重复 permit key 返回原 invocation 摘要、无 token 并关闭为 unknown；响应丢失必须核对，不能发新 token。凭据/配对码响应丢失应重新配对。发送者仍必须在本地持久化消费 invocation，实际点击前 GET claim 检查 may_execute。服务端不能将实际 UI 点击与数据库组成 exactly-once 事务。

设备撤销、重绑、学校停用、任务停止阻止新资格；已授予资格转 unknown。人工核实未发送必须等原窗口结束，再创建并确认新草稿；不复活旧 item。账号换机沿用同一规范身份，关闭旧设备 claim，移动绑定，不重置使用量。

## 限制与两通道互斥

- 账号滚动 24 小时默认 30、硬上限 50；群跨账号合计默认 10、硬上限 30；0 暂停。
- 同账号间隔至少 30 分钟；相同正文跨群/账号/学校至少 10 分钟。
- 同群相同正文历史成功/unknown 永久去重；同学校相同正文跨群分配冲突；同帖子 revision 的已投递冲突同样阻断。
- 准备领取按数据库群游标轮发；每群选最早 queued 项，跳过阻断群。扫描每次最多 100 群，跳过也推进游标以避免大量阻断群饿死后续群。
- 手机启用学校禁止新的官方草稿、确认、创建和提醒；保留读取、停止、核对。旧分享的 prepare 同样关闭。
- 同运营主体绑定账号参与已启用手机学校时，其他关联学校的官方新发送也保守关闭。学校关闭后，手机 unknown/pending 及最近 24 小时成功占用继续阻止切回官方群发，不能通过关闭开关清空约束。

official、legacy 通过来源唯一键投影共享账本。官方与旧分享写事务同步投影，worker 补偿历史，不以最终一致性替代资格检查。无法唯一映射发送账号的官方/旧记录按负责运营主体保守计入相关账号，不能任选一个账号放行其他账号。旧官方数据缺群映射或存在未核清执行时学校不能启用。v1 同步投影读取历史，采用保守串行策略；大量历史上线前需核对回填与吞吐，不宣称高并发调度能力。

## 部署与验收边界

总开关和学校开关均默认关闭。两个部署应用不变，新增 worker 跟随 API 优雅退出；关闭新资格不关闭已有结果回报和人工核对。数据库 forward-only，不删除旧表。回退必须保留理解共享占用的后端，不能恢复旧 binary 的发送写入。

外部执行器的真实群识别、无注入、人工速度及真机结果另行验收。本接口不能替代外部执行器验收。

## 2026-10-27：独立 Android 首批实现

`keeper-otter` 采用 Tauri 2 操作界面和 Kotlin 原生执行内核，首批只内置自有演示适配器，真实客户端尚未适配与验收。它不增加服务器部署应用。设备 result 的 reported_clicked_at 扩展为可空时间，避免未点击时填写虚假时间；旧非空输入兼容，null 保守 unknown，不改变单次资格、额度或人工核对规则。
