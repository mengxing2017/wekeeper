# ADR 0002：社区业务、学校边界与人工分享

日期：2026-10-21。

## 实现边界

Rust 单体承接身份、学校、社区、审核、分发、媒体、官方平台接入和审计。
审核事务在 community 中实现，与帖子/评论及 moderation_events 原子提交；不另建审核服务。
identity、schools、community、distribution、media 的用例通过 south/port::Store 调用 PostgreSQL adapter。
HTTP 层负责提取参数、身份和响应；SQL 位于数据库 adapter。
TypeScript contract 提供同源 client、CSRF、业务响应和错误类型；feature/api 是页面入口。

## 企业微信单企业边界

本项目仅支持一套企业微信配置，接入一个企业主体及其自建应用，不需要支持多企业同时接入。
部署使用唯一一组 `WEKEEPER_WECOM_CORP_ID` 与 `WEKEEPER_WECOM_SECRET` 作为服务端凭据；`WEKEEPER_WECOM_AGENT_ID` 仅保留旧配置识别兼容；群发、目录与 HTTPS OAuth 不依赖 AgentID。
目录属于唯一 CorpID，凭据指纹及递增代次隔离不同 Secret 的可见范围。补填 AgentID 不改变目录来源；更换 Secret 须经平台管理员显式验证并切换，旧任务与企业会话失效，账号绑定和学校授权保留。
企业成员 UserID 映射与客户群均属于该企业；新增群的 CorpID 必须与部署配置一致。
同一企业下可以管理多个学校、多个运营成员和多个客户群，学校范围与角色仍独立授权。
多企业凭证管理、跨企业成员身份与企业切换不在项目需求范围内，不作为业务缺陷或待建设能力。

## 身份与授权

浏览器使用 HttpOnly、SameSite=Lax Cookie，生产启用 Secure，修改请求同时检查 Origin 与 CSRF。
会话绝对有效期 8 小时、空闲有效期 30 分钟；每次请求重新读取账号状态和学校授权。
密码为 Argon2id。账号失败次数存 PostgreSQL，15 分钟窗口内 10 次失败后阻止继续登录。
微信小程序 code 在服务端交换 openid，使用独立 miniapp bearer 会话。
旧小程序 token header 只接受新生成的 miniapp 会话，不接受旧 PHP token，也不接受浏览器 Cookie。
企业微信 OAuth 使用一次性 state、HttpOnly state Cookie、5 分钟期限和固定回调路径。
企业微信成员从自建应用可见通讯录同步后，由平台管理员选择并实时核验绑定账号，再独立获得学校 operator/admin 权限；OAuth 不自动授予角色。
企业姓名、部门及状态与本地昵称、账号启停和学校授权分别维护。企业身份登录和发送准备实时核验成员，绑定版本参与会话及发送领取校验。
授权撤销保留 revoked 记录，普通学校绑定不能恢复被撤销的权限。
平台管理员可建学校、建账号、设置学校角色；学校 admin 可修改学校配置、群映射并核对分享结果。
普通成员只能操作授权学校内自己的内容和互动；审核与内容展示状态分开存储。

## 内容与分发

点赞和收藏分别存 kind，幂等设置/取消；浏览、互动和排序没有发送副作用。
模板仅解析四种白名单占位符，不执行表达式。新正文创建新版本，发布后不修改原版本。
群发任务有 posts/text 两种内容来源。posts 保存模板及已审核帖子 revision；text 直接填写规范化的纯文本，无模板和帖子关联，不发布到社区。两者均保存正文/哈希、学校与目标群/群主快照。每次编辑增加 revision，确认后不可变。
后台普通登录加明确学校 operator/admin 授权可创建任务；平台管理员无学校角色不能绕过发送授权。执行成员必须是官方群主、当前可见且绑定有效学校运营账号。
确认及 worker 领取前复核内容、群主、授权及凭据代次。按群主拆分，每批最多 2000 群，明确传 chat_id_list。正文采用官方 4000 UTF-8 字节上限，仅文本。
HTTP 创建使用独立无重试/无重定向 adapter；每批持久化单次调用资格，超时/响应丢失/领取后中断归 unknown，不自动创建重试。
企业微信成员仍需人工确认执行；msgid 不是送达证据。成员状态、逐群官方状态和人工核对独立，缺失群结果不推断成功/失败。
去重跨新群发和旧人工分享快照；并发确认按目标群锁串行。再次发送须 admin、来源和原因，未核对 unknown 及未停止的旧任务阻塞重发。
提醒/停止也使用幂等操作记录，停止不能撤回已发送消息。创建时停止覆盖迟到 msgid。API 内 worker 用数据库协调，不增加部署应用。
旧分享菜单与 SDK 发送页面已移除，/wecom 提示迁移；旧草稿/尝试保留历史读取和人工核对，不转换为官方成功。旧发送写接口拒绝；迁移兼容期允许已领取操作回报结果。
仅新增 forward-only migration，不改已应用 SQL。详见 docs/runbooks/wecom.md 和 report/28 实施方案。

## 媒体与兼容

首个媒体 adapter 使用 PostgreSQL BYTEA，单文件 5 MiB，限制 PNG/JPEG/GIF/WebP 文件签名。
这样本次交付不依赖未知的旧 CDN 凭证，并随数据库持久卷和备份保存图片。
这项选择替代原计划“直接接现有受控存储服务”；规模增长时在 media port 后替换为对象存储。
成员读取媒体需要学校授权；旧小程序 image 组件使用 15 分钟随机访问链接，日志不记录完整 URL。
上传资源尚无自动删除任务，保留策略由运维按数据库容量制定，不能视作完整对象存储生命周期。
旧整数链接通过 legacy_id_map 和独立整数别名映射；新业务实体保持 UUID。
兼容入口只负责旧表单、字段与 code/msg/data 包装，调用新业务用例。
旧短信注册、手机验证码和密码找回供应商不在本轮官方微信身份方案内；对应旧接口明确拒绝，不能返回伪成功。

## 迁移与上线

导出使用 MySQL 只读一致性快照；转换离线执行，未知状态、孤儿引用和无法读取的媒体阻止生成 apply.sql。
历史密码不复制；微信身份按 fa_third 映射，其他账号由管理员重置密码。
历史分享记录进入 historical_delivery_events，不转换成新系统“送达成功”。
重复应用同一个 source_hash 是空操作；增量以先前完整快照为基准，对比原值后更新。
新系统改写过的数据与旧快照冲突时，整个增量事务失败；硬删除要求单独审查。
迁移程序不自动停旧服务，也不自动切换生产流量。

## 客户群与学校群目录（2026-10-22）

客户群目录记录单企业自建应用可见的群及成员关系。按当前产品范围移除客户、跟进关系和客户联系成员目录；平台管理员读取客户群、群成员及运营成员的群主群数和参与群数。学校 admin 的候选群仅限自己已绑定且当前有效企业成员担任群主、未关联其他学校的群；候选查询及保存均重新核验成员。operator 只读本校已配置群摘要。

群及成员是一个原子发布数据集，staging 写入和发布均校验代次/租约。完整扫描缺失仅标记未见/待核验，不能推断已删除；失败保留旧数据。内部 UserID 使用 canonical key，外部群成员和群标识区分大小写。群内外部联系人不必已建立客户联系，不通过昵称/头像合并。

实现以 `wecom_asset_objects` 的 kind 分离两类规范化对象，使用命名视图提供群及群成员的逻辑关系；可选官方字段存最小 JSON，稳定身份、父关系键、成员比较键与状态单列并索引。关系解析通过同企业官方标识关联内部成员，未解析引用保留，不生成登录身份。学校目录关联使用外键、唯一约束和身份一致性触发器。学校显示名及冻结草稿独立于官方群名。

候选与当前统计排除超过 24 小时未核验的数据，这是本项目保守的新鲜度规则。历史失败群主只有在平台核对不可见错误并填写依据后才可从历史补扫排除；当前在职内部成员重新可见时仍会扫描。学校保存使用 generation、checked_at、绑定版本和实时群主校验，事务内重新检查账号/学校/角色，学校之间不得抢占已有映射。手填新群仅平台可用且必须定点核验，不代表已完成企业群枚举。

群主扫描范围只使用当前完整内部通讯录和历史群主，不调用客户联系成员或客户列表/详情接口。

群目录阶段未增加发送能力；2026-10-22 的 FE-03 群发实现按上文内容与分发规则接入官方任务，不增加回调入口。

直接文本内容未经社区审核，因此 operator 可保存草稿，确认提交仅限本校 admin；调用前再次验证确认人的 admin 权限。该检查不要求双人分离。重复检查不按内容来源隔离，直接文本与社区渲染的相同正文共用阻断规则。CRLF/CR 在直接文本保存前统一为 LF，预览、冻结、哈希和外发保持一致。

群发是服务端调用腾讯 HTTPS 接口，不依赖本系统浏览器 origin 的协议或 OAuth 登录模式。创建/提醒仅由服务端凭据、显式群发开关及学校用例授权共同控制；读取/停止不依赖创建开关。本地开发登录不绕过学校授权，也不额外阻止已授权的服务端群发。
