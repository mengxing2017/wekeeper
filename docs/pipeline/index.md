# 业务与发送流程

当前新业务使用[无环境前置批量任务 v5](../runbooks/dispatch-v5.md)。旧 v3/v4 文档仅适用于对应协议和历史在途任务。

## 身份、学校与内容

1. 平台管理员维护账号、学校及企业目录关联；学校内 operator/admin 权限独立授予。
2. 成员在已授权学校发布内容和图片，后台按审核策略处理；正文编辑可重新进入待审核。
3. 运营配置模板与版本、客户群和群主映射，再在学校工作区选择内容来源或直接文本。
4. 后端验证身份、学校、版本和冻结快照，记录审计。客户端页面可见不代替服务端授权。

媒体默认存 PostgreSQL BYTEA，随数据库备份；旧媒体与整数 ID 迁移采用明确映射，不猜测历史身份。切换与导入步骤见 [业务运行手册](../runbooks/business.md)。

## 官方企业微信群发

草稿 → 预览与人工确认 → API 内 worker 单次领取 → 官方创建任务 → 成员在企业微信执行 → 按群读取官方状态与人工核对。

直接文本确认要求本校 admin；官方 msgid 不是送达证明。创建、提醒、停止出现不确定结果时不自动重放，停止不能撤回已发消息。配置和真机要求以 [企业微信手册](../runbooks/wecom.md) 为准。

## 手机执行

人工确认冻结逐群任务 → 独立设备凭据领取 → 观察身份并准备 → 获取一次性 permit → 原生本地消费后单次动作 → 固定结果回报 → unknown 人工核对。

Android 为独立 keeper-otter 项目，WeKeeper 不新增电脑网关或任意远控服务。后端实现不代表微信/企业微信原生适配已验收，当前 Otter 只提供自有 demo 适配。

跨通道共享规范账号/群、额度、去重和 unknown 记录，不能切换设备或通道规避历史。设备接口、学校版本审批和回退顺序见 [手机执行手册](../runbooks/mobile-delivery.md)。

## 验收边界

类型检查、HTTP 契约或模拟平台测试不代表真实平台权限、真机行为或生产切换完成。先使用隔离数据库验证流程，再按运行手册逐项进行授权范围内验收。unknown 不自动解释为失败，也不以重试写入确认结果。
