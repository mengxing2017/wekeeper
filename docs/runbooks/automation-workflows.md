# 多应用业务配置与安卓应用准备

本轮只更新 WeKeeper 的后端、契约和 Web，keeper-otter 保持原状。新流程要求手机实现显式 v4；现有 APK 不会因此获得安卓桌面搜索、全部应用查找、验证采集或新版发送能力。没有真实环境和手机验证记录时，系统展示等待检查或待适配，不提供虚构的企业微信默认规则。

## 管理员入口

学校手机执行页面新增「手机与应用」「业务流程」「执行记录」，原策略保留在「历史发送策略」。平台手机管理页的「适配管理」替代原整包 JSON 工作台。

第一次设置分三步：

1. 选择已配对、启用且绑定了已核对账号的手机和企业微信。微信、钉钉、抖音是尚未支持的目录占位，不能用于发送。
2. 检查手机上报的安装候选、版本、通知、无障碍及解锁状态。工作资料或分身不能可靠区分时停止。候选来自手机，不要求填写包名或 UUID。当前 Otter 未实现 v4 时显示等待新版手机端，不需要反复重新配对。
3. 发起测试打开。手机必须显式接受任务；仅通过已验证桌面路径打开并核验应用，不搜索群、不写正文、不发送。Web 发起和查询任务均不等于授权手机自动操作。

业务配置分四步：选择已设置的应用/手机/账号，输入正文和有序群列表，设置群间等待秒数或分钟，复核服务端预览后确认。仅开放手动运行一次，确认后仍等待手机有效会话。管理员不选择规则发布或编辑 `rules/policy/baseline/evidence_ref`。

间隔不得低于已发布政策与真实人工基准的较大值。前一群结果明确回报后才开始群间等待，等待结束后才准备应用并搜索下一群。服务端其他账号/同文冷却可能继续延长等待；unknown 必须进入任务人工核对，不能自动重发或继续后项。

## 适配人员入口

平台维护人员还须具有试用学校的管理员权限。先从学校和手机应用列表选择范围，再通过页面标志、角色条件、导航步骤卡片、预算和政策字段建立不可变版本。所有条件均为非 ID 条件；包名和版本来自手机环境。页面和导航角色可以扩展，操作类型仅限引擎已经实现的有限动作。

组件分为安卓桌面、企业微信业务页面、执行政策及人工基准。基准只能从手机已完成的不同人工计时任务选择，不允许填写样本数或自行声明「已验证」。系统取样本各项耗时的保守最大值。基准优先在试用手机范围发布；跨设备复用仍须满足绑定及样本范围校验。

保存版本后发起手机验证。角色匹配和计时要求手机维护模式及平台维护权限；正常手机仅提供受限测试打开。政策验证需选择对应业务页面版本。桌面若启用两条路径，两条都须有同版本、同环境的成功记录才能发布。角色成功记录必须覆盖全部页面标志及业务角色且唯一匹配。

发布时选择成功验证和试用手机/当前学校的精确环境，证据关联自动生成。缺少验证时拒绝发布；被替代版本保留，撤销阻止后续准备和发送资格。维护表单的修改不会修改所选已保存版本，必须保存新版本并重新验证。

企业微信是外部系统：企业、账号、群、成员、消息 ID 以及 `resource-id/viewIdResourceName` 不参与手机定位或身份证明。本系统 UUID 只用于授权、关联、幂等及审计。群名后的 `(2)` 是成员数，按维护人员选定的标题解析格式处理，不属于群名，也不能全局剥除群名中的括号数字。

## 后端与数据一致性

新增迁移 `202610310001_automation_workflows.sql`，启动时按既有机制前向迁移。应用目录不代表某个真实安装环境已经获得发送支持。现有 v1/v2/v3 表、快照和摘要不改写；历史 v3 版本仍能通过既有 API 查询和恢复，不自动变成经过桌面验证的 v4 适配。

新增环境快照、应用绑定、组件版本/发布、验证任务/固定事件、冻结清单、业务预览和准备票据。业务转换仍创建原有 strategy/run/task/item 和有序游标，复用同文去重、额度、单次 permit 和 unknown 账本，没有第二套发送账本。编译生成的内部群聊规则包用于复用现有 handler，管理员不需要维护这个兼容包。

写操作与旧发送流程共用事务 advisory guard；发布、撤销、预览和确认在同一锁顺序下校验。确认绑定预览 revision、digest、当前环境代次、账号绑定和发布引用，变化后须重新预览；相同请求键恢复原结果，不重复创建业务。

清单冻结精确桌面、安装实例/版本、引擎能力和所有组件。环境检测快照有效期为 10 分钟，准备票据为 2 分钟，验证和预览为 10 分钟；这些是服务端协议租约，不是群间操作节奏。长等待后手机应重新报告环境：相同环境指纹允许为同一冻结清单取得新票据，真正的安装、实例或能力变化必须停止。重新上报代次会使尚未确认的旧预览失效；更新报告不延长原票据。

v4 清单摘要为按 Unicode 码点排序对象键的紧凑 UTF-8 编码（不能使用 UTF-16 默认比较器对非 BMP 键排序） SHA-256，整数时间、标准字符串转义、不含无意义空白。数组顺序保留，尤其不能重排目标群。Rust 和 TS 共享合成契约样例；真实 Kotlin 字节对照需随未来 Otter 实施完成。

## 接口与未来手机端接入

学校接口位于 `/api/v1/schools/{school}`：

| 资源 | 方法与用途 |
| --- | --- |
| `automation-apps` | GET 应用和已实现业务目录 |
| `automation-devices/{device}/applications` | GET 限定候选和环境状态 |
| `device-app-bindings` | GET/POST 应用安装实例绑定 |
| `device-app-bindings/{id}/capability-resolution` | GET 唯一适配解析和等待下限 |
| `automation-validations`、`/{id}`、`/{id}/cancellations` | GET/POST 验证创建、查看和取消 |
| `automation-business-previews`、`/{id}/confirmations` | POST 服务端预览和人工确认 |
| `automation-runs`、`/{id}` | GET 原有账本上的新版执行投影 |

平台维护资源位于 `/api/v1/platform/automation-adaptations`：`components`、`components/{id}/releases`、`releases`、`releases/{id}/revocations`。

新手机专用 `/api/v4/device-execution` 保留 enrolment/rotate/session/heartbeat/claim/prepare/permit/result/abort 语义，增加 `environment-snapshots`、`app-binding-resolutions/{binding}`、`validation-jobs`、`validation-jobs/{id}/acceptances`、`validation-jobs/{id}/events`、`execution-readiness`、`execution-readiness/{id}/events`（固定阶段，不授予发送资格）、`execution-readiness/{id}/completions`。仍使用专用 Bearer 凭据、JSON:API、稳定幂等键，不使用浏览器身份。四种协议配对共用原来的短码限次事务。

设备先恢复旧请求和固定结果，再处理有效会话、unknown 和群间期限；有当前项时才申请准备票据。票据不产生 claim/permit，只授权当前应用的可撤销准备。完成应用核验后声明本票据 generation/environment/digest，再领取当前项。claim、prepare、permit 均校验冻结清单和当前准备；应用内账号、群和正文核验仍须即时完成。

验证查询不会开始执行。接受需 revision/generation CAS，事件以 job/event_id 固定幂等。同机验证、准备和业务领取互斥；取消、过期后的晚到事件保留为未应用证据，不复活成功状态。尚在手机本地执行的操作需手机收到取消后关闭门禁，Web 不声称取消请求能瞬间撤回最后一次动作。

旧设备不能领取 v4；v4 也不借新路径重解释旧任务。历史 outbox 必须保持原路径、协议、key 和 body。停止、待核对、成功前缀沿用原任务流程。新版运行需要换规则或安装环境时，本轮选择停止剩余项并在向导重新预览，保留已成功和 unknown 记录；没有提供在线改写 v4 清单的入口。

## 检查与发布

```bash
make check-web
devbox run -- make check-backend
# 只使用显式的隔离测试数据库；包含新增 automation_* 集成用例。
devbox run -- make test-integration
pnpm --dir docs build
```

数据库集成用例覆盖验证取消后晚到结果、固定事件幂等、组件证据、普通学校管理员确认、清单冻结、旧设备拒领和应用准备门禁。需显式设置 `WEKEEPER_TEST_DATABASE_URL`，不得使用生产地址代替。无可用数据库或禁止 socket 的运行环境只能完成编译、领域/HTTP/前端检查，不能声称数据库并发和真机链路通过。

按后端迁移、Web、新版 Otter、真实环境采集/验证、受控发布的顺序接入。本轮没有修改或构建 Otter，没有执行手机导航或真实群发送；搜索和全部应用两条路径、停止/重启和安卓权限生命周期验收须在手机端实施后完成。
