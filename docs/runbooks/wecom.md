# 企业微信统一群发接入与验收

学校工作区“群发任务”提供草稿、人工确认、官方执行结果及异常处理。当前项目首次部署，没有存量人工分享数据、旧客户端或迁移兼容期。

## 配置与开启

单企业配置，Secret 只注入 API。群发使用 [创建企业群发](https://developer.work.weixin.qq.com/document/path/92135)，不会绕过成员确认。

| 配置 | 用途 |
| --- | --- |
| `WEKEEPER_PUBLIC_ORIGIN` | 浏览器 origin 与内容链接地址；不作为服务端群发的门禁 |
| `WEKEEPER_WECOM_CORP_ID` / `WEKEEPER_WECOM_SECRET` | 企业及配置到客户联系“可调用应用”的自建应用凭据 |
| `WEKEEPER_WECOM_BROADCAST_ENABLED` | 默认 false。完成下述检查后显式设为 true，开放创建与提醒 |
| `WEKEEPER_INSECURE_LOCAL_AUTH` | 生产必须 false；仅控制登录方式，不控制群发 |
| `WEKEEPER_WECOM_AGENT_ID` | 仅保留旧配置识别兼容，群发、目录及 OAuth 均不要求 |

开启前：确认应用具备客户联系群发及结果读取权限，执行群主在应用可见范围内；群主终端至少 4.1.10，指定 chat_id_list 时无需重新选群。目录读取成功不能替代群发权限验收。启用开关是部署方完成核验后的明确选择，不是程序已验证了权限或客户端版本。

本地 `devbox run -- make dev-embedded` 继承已 export 的环境变量，不自动加载 `.env`，退出销毁临时数据库。OAuth 仍关闭；群发不依赖 OAuth，本地调试也可在配置凭据并显式开启群发开关后创建真实任务。正文和任务集成测试使用 mock。

## 账号、群与操作

1. 同步企业通讯录与客户群目录，绑定运营账号，赋予本校 operator/admin。平台管理员单独身份不赋予群发权限。
2. 本校启用群须关联当前目录，数据在 24 小时内核验。执行成员取官方群主，且须绑定有效本校运营账号；不接受任意 sender。
3. 在“群发任务”默认直接填写纯文本，无需社区帖子或模板；也可切换到社区内容，选择 1–20 条已审核可见内容和已发布模板。选择 1–10000 个本校群后预览并保存冻结草稿，不调用外部创建接口。点击预览自动保存；无凭据或无目标群时可保留未解析草稿，不生成发送批次。
4. 查看完整正文、UTF-8 字节数、群清单及执行成员。修改草稿增加 revision，旧确认失效。正文最多 4000 字节，仅文本；不自动发送帖子图片。
5. 直接文本可由 operator/admin 保存，但仅本校 admin 可确认；社区内容沿用 operator/admin 权限。调用前撤销确认人的 admin 权限会阻止直接文本外发。人工确认后，任务按群主拆分，每批不超过 2000 群。在 API 进程由 worker 单次领取并创建外部任务，关闭浏览器不取消已确认任务。
6. 成员在企业微信执行；后台每约 5 分钟查询结果，也可手动请求同步。结果按群展示，成员已执行不等于所有群已发送，没有返回的群不推断失败。平台已发送不是已读回执。
7. operator 可提醒未执行成员，每批 24 小时最多三次；admin 可停止。停止不能撤回已发送消息。创建过程中请求停止，会在取得迟到 msgid 后继续停止。
8. 创建 unknown 不自动重发。本校 admin 在具体未决批次查询证据候选，按正文、成员、完整目标范围核对后确认结论。普通页面不填写 msgid；证据不足移交产品内负责人，不等于未发送。
9. 停止或提醒响应丢失时也不自动重试；在该批次核对表单选择对应结论并记录依据。重新发送从原任务生成草稿，默认只选没有官方成功证据的目标，必须 admin、原因及再次人工确认。

账号授权撤销、学校停用、内容变更、群主变化或凭据代次变化阻止尚未调用的批次，显示 preflight_failed / authorization_or_snapshot_changed。修复原因后创建新草稿，不自动复活旧批次。已创建外部任务不会因本地撤权撤回，应由仍有学校权限的管理员停止。

## 不确定结果与凭据轮换

一次外部写入前记录 invocation；领取后超时、断连、响应不合法或进程中断均不重放，超时领取在两分钟后恢复为 unknown。已创建但等待成员的任务没有两分钟执行时限。读接口可重试，写接口禁用 HTTP 重试和重定向。

服务端 Secret 轮换沿用企业通讯录“验证并切换服务端凭据”。旧代次任务不使用新代次盲目查询或创建。旧群发没有自动恢复查询开关；需要运维在原企业管理端核对/停止，记录人工证据，不直接改库或伪造成功。

关闭 `WEKEEPER_WECOM_BROADCAST_ENABLED` 暂停新创建及提醒；在有效凭据部署中，已有任务的读取与停止仍运行。网络/凭据失效时可能无法停止，必须到企业微信管理端核对；关闭开关不是撤回。

OAuth 回调仍是 `/api/v1/wecom/oauth/callback`，state 五分钟、一次性消费，成功后返回当前后台群发页。token 缓存仍按 CorpID/Secret 作用域隔离。旧 JS-SDK 签名和配置路由明确返回停用错误，公开能力字段 share_available 恒为 false；新学校级 `/broadcast-capabilities` 区分创建与管理能力。

## 首次部署

按 [部署运行手册](docker.md) 配套部署当前后端与客户端，执行前向迁移，再配置凭据、权限及有时效的真实交付观察。旧人工分享和旧分步模板接口均未注册，不提供历史读取、旧结果回报或草稿转换。开发数据库的重建与残留对象排查仍按部署手册处理。

## 验收

自动检查：`make check-web`、`devbox run -- make check-backend`、`devbox run -- make test-business`、`devbox run -- make test-embedded`。数据库测试只接受 `WEKEEPER_TEST_DATABASE_URL`，临时库入口自动创建并清理隔离 PostgreSQL。

真机验收需在经授权的测试企业：两个群主、多个目标群及非目标对照群，记录客户端版本、任务/批次/msgid、时间和实际消息；验证指定群范围、成员确认、部分拒绝、提醒、停止、权限撤销和跨校拒绝。此次编码未执行真实群发，生产权限及终端行为仍待该验收。

## 直接文本与无内容验收

正文 CRLF/CR 统一成 LF，拒绝纯空白、超过 4000 UTF-8 字节及不支持的控制字符；支持换行和制表符。无 HTML/Markdown/模板变量解释，普通链接只作为文本。修改草稿增加 revision，切换来源清空旧来源字段；确认后只能新建任务。

没有帖子/模板时，管理员可输入“【联调测试】这是一条客户群测试通知”，选择受控客户群，核对冻结正文并确认。该操作会创建真实企业任务，成员仍需确认。记录本地任务 ID/msgid、目标群消息和非目标对照群情况，不能用普通内部群替代客户群。编辑预览不外发；真实验收依赖服务端凭据、群发开关、群目录和成员授权；本系统使用 HTTP 或本地登录不会阻止服务端调用腾讯。

当前接口要求显式提交 `content_source`，不对缺失来源的旧请求推断 posts。任务始终保存完整编辑输入，草稿恢复直接读取该输入。

## 保存后仍是草稿 / 无法提交

保存草稿不会推送企业微信。任务详情核对正文与目标后，点击“确认创建企业微信群发任务”；直接文本须由本校管理员确认。确认后由后台创建任务，取得官方任务 ID，再由执行成员在企业微信群发助手确认发送。

确认按钮不可用时，详情显示业务状态及等待事项。业务人员可提交渠道申请，交付负责人按下节完成检查；不能只批准申请或开启开关就写“已交付”。恢复后仍须重新预览并确认。

### 开发与部署环境启用

本手册面向开发者和运维；业务页面只显示状态、申请和处理进度。部署方仍需配置 CorpID/Secret、腾讯应用权限、可信 IP 等条件，并显式设置 `WEKEEPER_WECOM_BROADCAST_ENABLED=true` 后重启 API。该开关不会自动确认现有草稿；新渠道还需要下节的真实交付观察。

本地调试可在启动 API 的终端配置 CorpID/Secret，随后运行：

```bash
export WEKEEPER_WECOM_BROADCAST_ENABLED=true
devbox run -- make dev-embedded
```

服务器访问腾讯仍使用腾讯的 HTTPS 接口。本地嵌入式数据库退出即销毁，调试者需在退出前核对外部任务；需要持续结果追踪时使用持久数据库。

### 有时效的渠道交付观察

这部分仅供部署负责人。凭据与显式开关保留原边界，另需当前企业、凭据作用域及代次匹配的交付观察。新渠道缺少观察、观察过期或暂停时禁止新创建；既有结果读取/停止独立判断。

`official-channel` 部署命令默认只校验参数，不连接数据库。`--apply` 才使用部署环境的 `DATABASE_URL`，只读查询官方任务列表并记录观察，不发送测试消息。必须提供真实外部权限复核来源；列表读取成功不能证明全部发送权限。

```bash
cargo run --locked --manifest-path backend/Cargo.toml --bin official-channel -- check --permission-review '真实权限复核工单引用'
# --actor 必须为预先受控配置的专用停用服务账号：无密码、无平台管理员权限、无企业/小程序登录绑定。
cargo run --locked --manifest-path backend/Cargo.toml --bin official-channel -- check --actor <服务账号UUID> --permission-review '真实权限复核工单引用' --valid-seconds 3600 --apply
```

`pause` 用同一参数形式记录暂停。检查期限为 60–86400 秒，部署方在真实复核后续期；不能循环写假通过记录。检查失败不写成功，旧观察到期后新发送停止；必要时主动暂停。凭据代次变化使原观察不再匹配。

所有渠道统一执行完整交付门禁：缺少有效观察时不能新发送，不从历史任务或目录状态推断交付完成。首次部署完成真实复核后，由部署负责人记录观察。

嵌入式数据库退出即删除；其中的任务记录应在退出前核对处理，已经创建的腾讯任务不会随临时数据库删除而撤回。需要长期追踪的任务使用持久数据库部署。

直接文本确认按钮因权限变灰时，由平台管理员在当前学校的“学校成员”页面勾选需要发送的账号，将“学校角色”设为“学校管理员”，保存所选成员授权。平台管理员账号也出现在该列表中，必须显式授予本校角色才具备对应群发权限；平台身份本身不代表学校群发授权。保存后会刷新登录会话中的权限。该操作不自动创建或发送任何任务。
