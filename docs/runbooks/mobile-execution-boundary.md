# 手机发送的执行边界

平台负责目标群名、消息正文、移动分发工作空间授权、业务发送间隔、资源调度、人工确认及结果核对。手机负责企业微信页面识别、群搜索、文字输入和本地执行适配。平台不安装或下发手机 UI 规则，也不要求测试手机或规则包才能创建、预览、确认任务。

新任务冻结 `execution: {contract: "device_owned/1", capability: "wecom.group_text"}`，不包含 `flow`、`flow_digest`、`release_id` 或运行配置标识。任务计划沿用 `shared_mobile_send/2`，设备执行使用 v10 `task-deliveries` 一次接收完整签名包；历史快照及结果身份保持原样。

平台在交付前完成候选与依赖核对。手机持久保存完整签名包后，在本地有效期和单次调用授权内自行识别群、准备正文并执行，不再联网申请许可、复核依赖或续租。群名的定位解释由手机负责，平台不指定选择第一个搜索结果。无法执行时由手机回报该次尝试的实际错误；可能已调用而无法确定结果时回报 unknown。手机离线、锁屏和本地适配失败只影响相应设备或尝试，不阻止平台受理业务任务。

已有手机客户端须支持 `device_owned/1`，将原本依赖服务端 flow 的执行入口改为手机本地实现。此仓库不包含该独立 Android 客户端；本次平台修改不声称已完成手机端适配或真实发送验证。旧客户端不得把缺少 flow 当作成功发送。

不确定结果保留 unknown 证据与重复风险，按现行期限继续候选换机；身份授权、移动分发工作空间边界、单次调用授权、设备物理互斥和配额继续生效。已交付包保留原快照，平台停止不能撤回离线设备持有的能力，迟到结果仍归原尝试。


新任务采用候选池调度：确认业务意图及本群全部有效候选范围，选择的手机只是首选。设备离线、忙碌、准备失败或调用前超时会触发下一合法候选，原设备恢复和静止证明不阻碍另一手机承接。调度轨迹及各尝试保留，不修改历史计划。所有候选暂不可用时保持已受理，在最多三轮完整候选遍历内重试（包含首次）。第三轮耗尽后报告下发失败并停止该目标的自动下发，手机上线和服务重启不重置预算；历史未知结果继续按原尝试补报。

尚未交付时，平台关闭失效尝试，阻止旧分配领取新包；已交付后离线、明确失败或接收后五分钟无最终结果时，按原授权候选切换设备，不等待原设备物理锁释放。该切换可能造成跨手机重复，原 unknown 继续保留。业务间隔约束新的合法分配，物理结算只释放相应设备。历史任务保留原单设备授权及顺序，不自动扩大候选。详细规则见[ADR 0008](../adr/0008-mobile-candidate-dispatch.md)。
