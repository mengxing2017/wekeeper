# 共享手机通用发送 v9

当前共享发送使用设备协议 v9、`shared_mobile_send/2`、FlowV3 与 `otter-ui/3`。企业微信官方客户群群发独立使用。平台内部编号仅用于授权和任务账本，不能充当企业微信的群 ID 或控件 ID；群定位使用实际搜索文字及可见页面条件。

## 部署与升级

API 启动自动执行前向迁移 `202611020115_shared_mobile_v9.sql`。先备份数据库和 `WEKEEPER_SHARED_SEND_KEY`，在隔离库检查迁移与旧任务风险，再同步部署 API、contract、Web 和新版 APK。各 API 实例必须使用相同的既有共享发送加密密钥；不得每次启动重新生成。新迁移不创建虚假适配、已同意授权、验收或生产范围。

当前首次部署没有历史任务或旧客户端兼容入口。手机、管理端和后端同步发布，使用当前协议；当前任务运行后产生的固定结果、unknown 和物理租约继续按原身份恢复，不能清库、卸载或重新配对消除风险。

## 使用开通与设备接入

平台或学校从[使用管理](../guide/platform-admin/shared-mobile-resources.md)选择范围并核对确认。系统在同一事务记录意图，后台持久重试资源关联；已批准范围内复用原额度，新增范围需要平台批准。

审批通过后直接关联学校共享资格、群绑定和业务范围，不再等待交付、验收或激活记录。已批准的使用范围按其有效期生效，不因手机等待超过 24 小时而要求重新申请。平台发送设置变化不使既有使用范围失效；实际执行同时遵守确认时与当前限制。手机离线不影响选择，运行前仍须本人托管、权限、解锁和自动检查。

业务运行不查询交付记录、人工验收、发行激活或 APK 摘要白名单。实际执行规则仍须存在且未撤回；后台自动选择最新未撤回规则，确认后的任务冻结原规则。当前仓库没有真实企业微信内置规则，不能将合成测试规则用于生产或宣称首次安装即可发送。规则缺失属于产品实现缺陷，不阻止预览、确认、任务入队或手机领取。手机实际准备时若缺少规则，明确回报调用前失败，任务详情显示未发送原因；不要求管理员补技术材料。

## 两步发送

学校选择群并输入正文后直接预览，服务端一次请求自动保存草稿并生成生产发送计划。管理员核对后点击“确认发送”；取消阶段选择及重复确认勾选。有效的学校手机群绑定可直接作为任务范围，无须额外登记测试或生产放行；已有使用管理的停用、期限及额度仍有效。提交失败弹窗显示原因并保留预览。候选手机可离线，只有当前运行条件未满足时任务可以确认后等待。

预览冻结授权映射和实际搜索名。定位、设备、资格或授权修订变化重新核对，不能自动替换确认。使用授权续期形成新版本、共享累计额度，不延长原任务确认和许可。

## 严格逐群与恢复

同一任务共享一个全局游标，即使分配给不同手机也不并行搜索后群。上一群结果先落账，原手机校验原回执并确认界面空闲，再开始持久等待；间隔取确认时冻结政策、当前政策、人工基线及学校设置的最大值。手机还执行单调计时，重启后重新等待完整间隔，不能因墙上时钟跳变缩短等待。等待前后不提前进行后群搜索、检查或准备。

手机从任意前台 Home 返回桌面，按已发布搜索/全部应用路径打开企业微信，核实前台包，然后导航群搜索和聊天。已在可识别目标应用时可直接继续；无安全返回路径、已有他人草稿、分身歧义或身份异常时停止。规则不要求企业微信版本登记，也不先上报环境清单。只有实际检查或执行失败才另行上报有限版本诊断，诊断不可得不阻止固定结果补报。

调用前先持久化并一次消费许可；结果不确定记 `unknown`，整机及目标风险阻断，不自动重发或改派。管理员只有基于真实证据核对为已发送或未发送后才能推进或另行安排；未发送的改派仍要求旧物理所有者静止。停止仅阻止新许可，已有许可继续结算。断线/重启只恢复原请求与结果，不重新点击。

## 故障办理

使用管理分别显示审批、使用状态和手机现场原因。学校点击“报告问题”补充实际情况，系统关联现有诊断；平台在同一使用对象查看问题。应用规则修复属于产品维护，不是业务管理员的前置操作，不要求学校采样或补验收表。

自动检查保留依赖去重、每日预算和退避。未决调用、结果回报、结算和人工核对继续使用原身份和许可约束。

## 发布检查

执行 `make check-web`、`devbox run -- make check-backend`、`make docs-build`；数据库并发/隔离测试仅使用显式的 `WEKEEPER_TEST_DATABASE_URL`。手机执行自身构建、契约、原生和文档检查，然后分别构建 x86_64 AVD 与目标真机 APK，执行 `apk:check` 和实际安装联调。

源码通过不等于 APK 或业务验收完成。必须记录 APK 摘要、实际代码版本、隔离后端、设备与用例证据，逐项完成两条桌面路径、离线可选/恢复、同机与跨机两群、ACK 丢失、unknown、撤回、并发激活及 72 小时观察。未实际执行的项目保持未验收，不能批准生产。

## 平台业务方案与发送状态

“手机群消息使用管理”顶部分别显示系统默认或平台实际执行设置；每台手机是否具备执行条件由目标群的检查结果分别展示。学校使用授权和手机现场状态分别在使用列表展开查看；审批通过不代表手机在线或实际应用界面可以识别。

业务管理员不办理文件导入、证据提交或技术验收，应用适配与执行条件由系统内部处理。

平台管理员在同一页面打开右侧“配置业务方案”抽屉，设置发送开关、IANA 时区、允许时段及平台/学校/手机/群四维额度和间隔。未保存方案时使用系统默认设置：允许执行、Asia/Shanghai、每周七天全天；四维限制均为间隔 30 秒、每小时 30 次、每日 150 次。平台可按需调整，无需先保存方案才能提交任务。业务设置不依赖技术交付，可先配置开放；实际发送仍需系统支持且手机就绪；学校角色没有平台方案写权限。

保存需要变更理由、明确核对确认和当前修订，形成不可变版本并记录操作者。时段、四维限制或间隔变化不要求重新办理学校使用范围；收紧即时限制新许可，关闭停止新许可。暂停再开放且方案实质未变时不要求重复办理授权。重新申请沿用既有预算根，不重置累计消耗。已发单次许可保留原结果凭据与结算，unknown 继续人工核对。

任务受理不依赖实际执行开关：未配置时使用系统默认设置；明确暂停时仍可预览并确认排队，领取与实际许可等待恢复。手机离线、忙碌或运行状态未同步单独显示为执行条件，不禁止确认。状态缺失或过期不代表撤回托管或缺少权限，只有明确上报才显示对应状态。学校无需选择内部测试/生产阶段；旧方案只支持测试时应由平台重新保存当前业务方案。产品技术升级只更新执行能力，不覆盖平台时段和业务额度。

## 使用对象、定位与续期

开通预览、资源协调和任务依据均按手机与群的有效定位处理；覆盖名存在时使用覆盖名，不与目标群默认名强求相等。摘要后手机有效定位变化需重新预览，不自动替换已确认任务。协调逐项核对已有资源快照，进度说明包含手机、群及已关联数量。

重复开通不另建相同业务的预算；续期和重新申请保留 supersedes 来源及 budget_root 累计消耗。主列表折叠同一预算族的版本，历史记录与任务引用保留。同一旧版本已有后继时，从最新版本继续操作，不继续分叉。平台账号和学校账号采用一致的重复范围复用规则。

前向迁移 `202611030120_mobile_usage_lineage.sql` 仅为来源关系增加索引，不删除历史数据或重置预算。同步部署 API、contract 与 Web。既有无来源关联、独立预算根的重复记录不会自动合并，避免误改已经形成的任务和预算关系。
