# 共享手机通用发送 v9

当前共享发送使用设备协议 v9、`shared_mobile_send/2`、FlowV3 与 `otter-ui/3`。企业微信官方客户群群发独立使用。平台内部编号仅用于授权和任务账本，不能充当企业微信的群 ID 或控件 ID；群定位使用实际搜索文字及可见页面条件。

## 部署与升级

API 启动自动执行前向迁移 `202611020115_shared_mobile_v9.sql`。先备份数据库和 `WEKEEPER_SHARED_SEND_KEY`，在隔离库检查迁移与旧任务风险，再同步部署 API、contract、Web 和新版 APK。各 API 实例必须使用相同的既有共享发送加密密钥；不得每次启动重新生成。新迁移不创建虚假适配、已同意授权、验收或生产范围。

“查询历史 v8 任务与风险”可查看原账本、停止历史未许可工作或核对 unknown；不提供新建、确认或改派入口。旧 v8 Journal 保留原协议补报、恢复和核对。通用发行激活后停止旧 v8 新领取；无许可的旧任务由管理员停止，必要时另建计划并确认。旧许可、unknown 和物理租约仍阻止同机新操作，不能清库、卸载或重新配对消除风险。既有 schema/1 托管范围与摘要一致时保留本人同意；旧 v7 能力同意不自动升级。

## 先办理通用能力

入口：“共享手机与目标群 → 业务能力开通”。普通学校管理员不维护技术规则；平台维护人员使用“通用能力办理”，所有编号、摘要和修订由界面处理。

1. “配置通用流程”：填写真实页面的文字、无障碍描述、控件类型与所属容器条件，配置入口、搜索、群结果、聊天以及安全返回路径。分别配置“桌面搜索路径”和“全部应用路径”。不能把仅有“可见”属性的空条件当真实规则。标题可选完整一致或忽略末尾成员数，例如 `(2)`、`（2）`；群名本身的其他括号不删除。
2. 上传本次实际安装的 APK 和现场证据。平台计算摘要，可在证据文件表“下载审阅原文件”；文件仅限平台管理员读取，下载强制作为附件且不缓存。候选验证由手机原生核对自身安装包摘要，不通过手填哈希办理。
3. “申请人工操作采样”：选候选流程和测试手机，手机本人点击“开始人工操作计时”，按约定完整步骤人工操作后点击“完成操作并结束计时”。至少三个真实样本和现场证据用于“记录人工间隔基线”。中断样本不能伪造补齐。
4. “发起无发送验证”：选择候选流程、已有目标绑定、实际 APK，分别创建桌面搜索与全部应用验证。本人托管、权限、解锁、后台在线满足后执行。验证只做可见导航与控件核对，不取得消息正文和发送许可；无需先激活发行或具备生产验收。
5. “冻结候选发行”：选择同一流程的人工基线和证据。发行的逐群最小间隔不得低于真实样本最大值；不满足时复制为新候选、调整并重新采样。
6. “记录能力验收”选择“有限测试”：选同一流程、相同实际 APK 下两条已通过的有效验证和证据。有限首测无需先有成功发送或 72 小时记录。
7. “激活通用发行”：平台以修订检查切换唯一生效指针；并发办理者需刷新后重试。历史发行数量不作为冲突依据。
8. “批准业务范围”：选择能力验收、学校、明确的手机和目标群、调用上限及有效期。有限测试最多 20 次、有效期少于一天、不自动包含新增群。学校资源池资格修订同时冻结；范围变更须另行办理。
9. “配置发送政策”：选择启用及“限定测试”，配置时区、允许时段、四维额度/间隔、确认有效期、检查有效期和自动重试预算。政策模式分别为禁用、仅草稿、仅预览、启用；阶段与模式独立。

生产需另行完成 S01—S40、T01—T14、真实有限测试发送、历史风险清理、72 小时实际托管观察及证据审阅，办理生产验收和业务范围，并在政策中允许生产阶段。单元测试、合成 fixture、APK 摘要或勾选表单本身均不证明真机通过。产品能力验收可复用，业务范围按学校/手机/群冻结，每个绑定仍执行自动无发送检查。

## 手机与学校操作

1. 平台登记并配对手机，批准学校使用手机；学校维护目标群实际搜索文字并绑定共享手机。平台直接配置的具体群绑定也可使用。
2. 手机进入“共享手机托管”，点击“查看范围并启用托管”，在原生弹窗确认平台和用途；再设置通知、无障碍、解锁及“平台连接与长期托管”。普通重启、重连和适配更新不要求重复同意。可以随时暂停、恢复或撤回。
3. 学校“手机任务 → 手机共享发送”按执行顺序选择多个群，填写正文、阶段与间隔，“保存草稿”后“预览逐群执行计划”。手机候选基于有效资源绑定；离线、待首次授权、缺权限或检查未通过不将候选从下拉框移除。
4. 三种状态独立：可计划、可确认、可执行。缺少有效发行、政策、业务范围或存在风险时不能确认；只有运行条件尚缺且静态范围有效时可以确认进入等待。学校管理员核对实际群序、手机、搜索文字及完整正文后明确确认。手机未授权/未就绪时绝不操作 UI。
5. 预览为固定快照。状态变化仅提示，不静默换手机；重新预览清除确认。定位、绑定资格、凭据代次或发行变化须重新确认。确认到期后不继续发送，可在任务详情“复制原意图为新草稿（需重新确认）”。复制不恢复原许可。

正文保留有效空格与换行，不把 UI 成功动作当作对方送达。默认按群分类容器内视觉顺序选择首个群结果，并核对结果标题与聊天标题；同名/多实例/不唯一控件不能猜测。

## 严格逐群与恢复

同一任务共享一个全局游标，即使分配给不同手机也不并行搜索后群。上一群结果先落账，原手机校验原回执并确认界面空闲，再开始持久等待；间隔取确认时冻结政策、当前政策、人工基线及学校设置的最大值。手机还执行单调计时，重启后重新等待完整间隔，不能因墙上时钟跳变缩短等待。等待前后不提前进行后群搜索、检查或准备。

手机从任意前台 Home 返回桌面，按已发布搜索/全部应用路径打开企业微信，核实前台包，然后导航群搜索和聊天。已在可识别目标应用时可直接继续；无安全返回路径、已有他人草稿、分身歧义或身份异常时停止。规则不要求企业微信版本登记，也不先上报环境清单。只有实际检查或执行失败才另行上报有限版本诊断，诊断不可得不阻止固定结果补报。

调用前先持久化并一次消费许可；结果不确定记 `unknown`，整机及目标风险阻断，不自动重发或改派。管理员只有基于真实证据核对为已发送或未发送后才能推进或另行安排；未发送的改派仍要求旧物理所有者静止。停止仅阻止新许可，已有许可继续结算。断线/重启只恢复原请求与结果，不重新点击。

## 故障办理

就绪详情分别显示发行、政策/业务范围、授权、连接、运行条件和检查。学校使用“申请适配支持”说明实际失败步骤；平台在“适配支持”“失败诊断”查看受控记录，用“处理适配支持”记录调查、关联修复发行、答复或不受理。所有办理校验角色、学校范围、修订和幂等键，并保留审计。

自动检查按依赖去重、每日预算和退避执行；“重新评估自动检查”不会重置预算。修复实际流程后复制新候选并重新验证，不通过清除风险、伪造环境或手工 SQL 解除限制。

## 发布检查

执行 `make check-web`、`devbox run -- make check-backend`、`make docs-build`；数据库并发/隔离测试仅使用显式的 `WEKEEPER_TEST_DATABASE_URL`。手机执行自身构建、契约、原生和文档检查，然后分别构建 x86_64 AVD 与目标真机 APK，执行 `apk:check` 和实际安装联调。

源码通过不等于 APK 或业务验收完成。必须记录 APK 摘要、实际代码版本、隔离后端、设备与用例证据，逐项完成两条桌面路径、离线可选/恢复、同机与跨机两群、ACK 丢失、unknown、撤回、并发激活及 72 小时观察。未实际执行的项目保持未验收，不能批准生产。
