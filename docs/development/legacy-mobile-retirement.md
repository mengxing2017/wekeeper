# 旧手机维护协议退场

旧 v4/v5 维护、学校发布与账号执行链路停止新增；v7 能力开通和限定目标的现场检查独立保留。官方企业微信客户群、群发任务及历史外部调用台账不受影响。

## 用例与接口

`mobile_delivery::Command::require_not_retired` 在仓储完成平台、学校或设备身份授权后执行，早于幂等结果重放和业务写入。合法旧写入返回 JSON:API HTTP 409 `legacy_mobile_maintenance_retired`。匿名请求仍走身份错误；停用错误不查询或披露历史资源是否存在。

| 范围 | 停用 | 保留 |
| --- | --- | --- |
| Dispatch v5 | 请求/接受验证、流程/基准创建、发布、设备组与分配、启用、预览/确认、重建剩余项、收件回执、准备租约、阶段推进与准备 | 查询、取消验证、撤销发布、停用、暂停/停止批次、固定验证事件、失败证据及诊断补报、授权回执与心跳 |
| Automation v4 | 环境/绑定新增、请求/接受验证、组件创建/发布、预览/确认、执行准备及应用就绪 | 历史查询、拒绝/取消验证、验证事件、撤销发布、授权回执 |
| 通用旧执行 | 配置创建/发布、策略新建/修改/运行、草稿/预览/确认/重发、领取/续租/准备/单次许可及启用学校 | 停止、撤销、原结果/中止回报、unknown 核对与历史读取 |

旧 `/api/v4/device-execution/validation-jobs`、v5 设备维护队列与 dispatch inbox 对已认证的对应协议设备返回空集合，不投递任何旧控制动作。旧学校能力读取固定 `create=false`、`confirm=false`、`claim_enabled=false`，原执行资源固定不可用；不能用开关重新开启。

SDK 的历史写 client 保留用于明确暴露停用错误，并标记废弃；当前能力页不引用它们。Rust 序列化与 TS 错误解析共用 `legacy-mobile-maintenance-retired.json`。

## 数据迁移与回退

迁移 110 记录退场时间和迁移前状态计数，将未开始的 v5 queued / v4 queued、offered 验证取消。所有旧验证带 `retired_at`；已接受/运行作业不修改原 revision、generation、凭据代次及有效期，保留原窗口终态补报。v5 历史文档不要求设备现在仍有旧账号绑定；退场作业结果不授予新执行资格。

迁移不给已接受作业伪造终态，不删除证据、许可、已调用或 unknown。新 v7 检查领取会检查旧 accepted/running 作业，原有效期内保持物理设备互斥。单连接 SQL 回归覆盖此边界，不宣称完成多连接压力测试。

旧维护/发送表的创建与激活触发器阻止旧后端重新插入作业或发放许可，允许取消、终态回报及核对。触发器是防御措施；**后端不得回退至不含停用检查的版本**，旧二进制可能重放旧幂等响应。Web 回退或旧书签不改变后端停用规则。

## 手机端边界

keeper-otter 对协议 4/5 显式停止维护轮询、自动调度和验证启动；每次旧验证动作守卫都会拒绝。手动补报不经过启动门禁，不执行 UI。

本地已有接受记录在重启后形成固定 interrupted 结果并补报。接受请求结果不明时，空队列不再清除本机记录，显示人工核对原因，不重跑或猜测未执行。已固定结果按原请求补报；平台拒绝时保留记录。

存量旧 APK 的停止仍依赖服务端空队列、其原有取消观察与到期守卫；不能把服务器取消写入解释为手机动作已瞬时撤回。上线时需核对在途作业、升级执行端并等待原控制窗口结束。

以上是旧协议退场记录，不能作为当前共享发送的业务就绪判断。当前执行状态由真实手机条件及任务状态决定，不因历史研发验收记录阻断。
