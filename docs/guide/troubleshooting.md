# 按现象查问题

适合所有使用者。先保存站点环境、发生时间、页面名称、学校和错误文字；不要提交密码、Secret、设备令牌或完整聊天内容。

| 现象 | 下一步 | 处理人 |
| --- | --- | --- |
| 登录失败 | 核对账号、密码和启用状态 | 平台管理员 |
| 没有学校或菜单 | 核对学校有效状态及单独授予的学校角色 | 平台管理员 |
| 平台管理员不能确认本校任务 | 检查是否拥有本校要求的业务授权 | 学校/平台负责人 |
| `directory_snapshot_required` | 先完整同步当前企业通讯录，再同步客户群 | 平台管理员 |
| 同步失败但仍有旧数据 | 查看最近成功时间；旧快照不等于本次成功 | 平台管理员 |
| 学校客户群候选为空 | 检查目录、核验时间、群主身份、成员绑定和他校关联 | 学校/平台管理员 |
| 官方群发能力关闭 | 核对服务端开关及官方平台权限 | 部署负责人 |
| 官方任务创建后未送达 | 请执行成员到企业微信确认，再看逐群结果 | 执行成员与学校管理员 |
| 手机待升级或离线 | 核对执行端版本、网络、授权；任务可以排队 | 手机负责人 |
| 预览按钮不可用 | 逐项检查所选设备账号、群、正文、间隔和学校配置 | 学校管理员 |
| 数据已变化 / 版本冲突 | 刷新后重选，重新阅读预览 | 当前操作者 |
| 结果不确定 | 到原任务人工核对，保留证据 | 有核对权限的负责人 |
| 页面可打开但接口不可用 | 检查 API 就绪、数据库和代理，不清空数据 | 部署负责人 |

## 联系维护人员前

1. 在原任务看最新状态，不只截图列表。
2. 记录自己已经做过的操作，说明是否可能已经发送。
3. 按[结果处理](operator/results-and-recovery.md)保留未决任务；不要重复确认、切换设备或新建同文批次。
4. 如需日志，由维护人员按任务标识关联，日志不应包含凭据或真实聊天全文。

部署故障见[运行与故障处理](../operations/index.md)，技术检查见[测试与验收](../development/testing.md)。
