# 手机执行配置

手机执行配置与官方客户群及官方群发分别管理。学校管理员维护配置，运营人员只读；平台管理员代办仍需本校管理员权限。

## 准备顺序

1. 平台管理员在“学校设备授权”为手机明确授予学校及用途。
2. 在手机上确认平台来源，接受该学校当前用途授权。用途或授权版本变化后需要重新接受。
3. 在业务区“手机执行配置”登记流程维护人员提供的新版流程文件。文件必须为 schema v2、业务协议 v6，使用独立的群分类容器与首群结果规则。
4. 选择本校设备和流程，填写现场测试群搜索文字后创建验证。搜索文字按原文用于首群定位，仅用于此次不发送消息的验证，不会自动新增业务目标或发送任务。验证有效期 30 分钟，只观察应用、搜索结果、群会话和发送控件，不点击发送。
5. 设备报告全部检查通过后，管理员在 24 小时内明确确认发布。更晚的失败验证、凭据代次或授权变化会阻止使用旧验证发布；静态校验通过不能代替设备验证。
6. 为本校设备分配已发布流程。每校每设备一份配置；换流程或启停使用当前执行版本，旧页面提交冲突时刷新后重试。

“等待手机验证”表示尚无设备回报；“设备报告验证通过”仅表示设备报告观察通过，不表示平台识别了真实账号、真实群身份或消息送达。其他设备使用相同发布流程时，仍需各自验证。设备授权或流程发布失效时配置不可用；仍可停用失效配置。

## 流程维护边界

流程文件由维护人员根据现场可访问的界面编写，禁止脚本、坐标、资源 ID 或第三方账号身份。必须提供页面、控件条件、桌面搜索入口、导航、人工节奏基准、稳定等待和步骤/滚动/时长/目标数预算。群结果只从指定群容器内按视觉上下顺序取首项；其他关键控件仍要求唯一定位。发送按钮不得作为通用导航动作。

契约目录的 `mobile-execution-flow-v2.json` 是测试格式示例，控件文字为占位内容，**不是可直接用于真机的已验证流程**。不要将测试基准或占位选择条件用于正式发送。

## 当前接入状态

已实现服务端登记、设备验证任务与回报、发布、撤销、配置和状态查询。新版手机授权页已接入学校用途确认和不发送消息的现场验证；请在手机上刷新并明确开始，旧手机端不会执行新版验证。新版“手机任务”已支持预览、确认登记与取消未领取任务；设备领取、调用许可和结果核对尚待接入，“配置准备完成”或“任务已登记”不代表当前版本已经可以发送。撤销发布也不能撤回已经发出的许可，相关调用仍需按原证据核对。
