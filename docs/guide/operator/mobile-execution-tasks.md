# 手机群消息两步发送

进入“移动端分发管理 → 手机任务”。先在“手机群消息使用管理”开通手机和目标群；范围尚未批准时办理手机和目标的使用授权；离线、锁屏或本地准备失败时由系统在授权候选内继续调度。系统不管理手机 UI 规则，手机适配问题不阻止创建、预览和确认任务。手机通过认证 WSS 连接直接接收完整签名执行包，持久保存后在包的有效期内直接本地执行，不再申请执行许可、联网复核依赖或续租。不支持或准备失败须回报该次未执行原因，不要求系统安装手机规则包。

1. 按执行顺序选择全局目标群，输入完整文字，点击“预览”。系统自动保存草稿；不选择研发阶段，也无需另点保存。
2. 核对完整文字、唯一目标群名和全部授权候选手机，点击“确认发送”。这是实际发送确认，不再重复勾选相同确认框。所选手机为首选；同时确认本群全部有效授权候选，首选不可用时系统自动换机。

文字的有效空格和换行保留。预览后修改文字、群或间隔须重新预览；候选范围内自动换机记录完整轨迹，不重复确认；正文、目标或授权范围变化需重新预览确认。

详情保留逐群状态、停止、人工核对和改派。停止会阻止后续可控交付，不能收回手机已经持久保存的执行包；已交付或在途尝试仍可执行并回报真实结果。当前手机离线、明确失败，或接收任务后 5 分钟仍无最终结果，系统自动选择下一台合格手机。unknown 保留历史证据和风险记录，但不阻止超时切机；切机可能造成重复发送。旧任务确认到期后须复制为新意图再确认，续期使用授权不会延长旧任务。

不同目标独立调度，遵守确认的业务间隔；某群或手机故障不拖住无关目标。原手机结算只影响该手机资源。手机使用者在手机端管理本机意愿、系统权限和后台连接，平台不查询或操作这些偏好。


## 任务是否已经到达手机

确认后在任务详情区分两个状态：

- **系统已创建，等待手机同步**：任务已入库，系统还没有收到手机持久化成功后的接收记录。设备在线本身不代表已经收件。
- **手机已接收，等待执行条件**：手机已保存任务摘要。接收记录不代表已发送。新任务同时显示目标调度状态、授权候选和自动换机历史；原手机故障时不要求手工重新提交。

手机“任务”页面提供“已接收任务”和“最近结果”，未领取的后续群也会显示群名及任务中的顺序。点击“刷新任务”仅更新列表，不会确认发送或启动企业微信。列表读取独立于无障碍、解锁和执行恢复；断网时保留上次任务并标记过期，首次同步失败不显示为空任务。

手机自动补报接收状态，不需要使用者逐任务确认。接收补报失败会后台重试，不会阻止直接接收或本地发送。平台继续核对管理员确认、业务范围、设备身份和单次调用授权；手机自行处理本地执行条件。

### 下发失败与轮次上限

每个目标最多完整遍历授权候选手机 3 轮（包含首次），每轮至少等待 5 分钟。只有一台手机且一直无反馈时，三轮约 15 分钟（另加固定扫描延迟）；已领取任务不会因心跳暂时过期或暂停而提前结束本轮。第三轮全部候选失败或不可用后，显示“任务下发失败”，停止该目标的自动下发；其他目标继续独立调度。包生成后 60 秒无接收确认且无结果，或首次确认接收后 5 分钟无最终结果会切换候选，业务间隔等待不消耗轮次。

手机上线、页面刷新、服务重启和人工改派均不能重置耗尽预算。再次发送请复制原意图为新草稿并重新确认。历史结果未知不表示确定未发送，迟到结果仍会记录，迟到成功可修正目标结果。

所有目标结束后，任务详情停止自动轮询；可点击“刷新”查看迟到结果。仍有活动目标时继续自动更新。

逐次尝试显示证据来源和平台记录时间。“设备反馈发送成功”表示手机本地观察，不是官方验证送达。设备提供本地完成时间时会单独显示并标记未校时；该时间不改变平台五分钟结果期限，旧手机没有提供时间仍可正常补报。

任务列表直接显示系统汇总状态，无需先打开逐群进度：全部目标已发送显示“任务已完成”，手动停止未完成任务显示“任务已手动停止”，三轮耗尽显示“任务已停止自动下发：三轮下发失败”。仍有目标执行时显示“任务正在调度”。完成结果优先于停止标记，完成后再停止或停止后补报全部成功，都保留“任务已完成”。

## 自动任务下发记录 {#automatic-dispatch-records}

在“移动端分发管理 → 自动任务下发记录”查询来源消息进入手机分发领域后的处理。默认查看自动来源，可按消息回执、消息、接入记录、任务、目标群、手机、阶段、结果、原因和时间筛选。任务创建失败也有记录，任务 ID 显示“尚未创建”；列表使用服务端筛选和分页，不局限于最近 100 条任务。

先看“当前停留位置”和候选具体原因，再打开完整记录：创建处理与调度评估逐次保留，展开可查每台候选当时的检查证据；交付交互显示手机请求和平台决定；事件时间线保留原尝试及迟到结果。当前原因与历史曾发生原因可以分别筛选，历史判断不会被手机当前在线状态覆盖。

`awaiting_round_deadline` 表示本轮候选已耗尽，等待本轮截止后重新评估。查看同轮候选的具体排除原因和“下次重评”时间；系统此时没有立即继续下发，候选中途恢复也可能等待剩余轮次窗口。每轮至少五分钟、最多三轮，接收后五分钟无最终结果的换机规则独立生效。

执行包生成、服务端连接写入和手机落盘接收是三项不同事实。服务端写入完成不能证明手机收到。交付表按原 execution_id 展示每次推送、接收截止、落盘确认、结果截止与原改派原因；接收确认超时表示是否实际收到未知。迟到确认及结果保留原尝试身份和超时记录，不覆盖后继设备。

“最近真实进展”“最近检查”“观察时间”分别代表业务推进、实际评估和本次读取，反复刷新不会延长业务期限。读取失败须先重试读取，不能据此认定记录不存在。记录查询不会补发消息、扩大授权范围或改变来源接收回执；再次发送继续按创建新任务的业务流程处理。
