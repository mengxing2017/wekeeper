# 结果、暂停、停止与异常核对

适合业务负责人和有相应操作权限的分发管理员。开始前找到原任务/批次，确认工作空间、时间、目标群和发送通道。

| 看到的现象 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 官方任务已创建 | 请执行成员到企业微信继续确认，读取逐群状态 | 不把创建成功当成送达 |
| 手机离线、排队 | 查看自动调度和换机记录；全部不可用时系统持续寻找资源 | 不为同一消息重复建批次 |
| 手机锁屏、权限不足 | 系统跳过不可用手机；手机使用者可处理本机条件，不要求业务重新提交 | 不把权限错误当作流程适配成功 |
| 暂停 | 核对暂停原因、剩余项和未决结果后再恢复 | 不跳过前群的等待与结果核对 |
| 已停止 | 查看已发和未发范围，保留证据 | 不理解为撤回消息 |
| 确定失败、确定未发 | 查看原任务的修订/剩余项入口，重新预览确认 | 不把所有失败都当作可以补发 |
| 结果不确定 / unknown | 人工核对真实群记录、官方任务与原账本，记录依据 | 不自动重试、不换通道绕过 |

## 核对步骤

1. 保存原任务名称、发生时间和系统错误文字。不要删除历史记录。
2. 请负责该发送账号的人检查真实群/官方任务，确认是否可能已经发出。
3. 官方任务在具体未决批次点击“查询当前工作空间可核对证据”，核对正文、成员、目标范围及时间，选定候选后确认结论；不需要填写官方消息编号。没有候选、证据不足或查询失败不代表未发送。
4. 无法判定时在原任务填写现象并移交负责人，系统携带任务与批次上下文，在申请/问题列表跟踪处理，保留不确定状态。
5. 新任务对确定未发送的目标在原确认候选内自动换机，无需重建任务；扩大候选范围或改变正文、目标才重新预览确认。历史单设备任务需要候选池时复制为新草稿。
6. 成功项、unknown 和可能已发送的项不能进入剩余项重建。原未决结果必须先处理。

完成后应能找到原任务、判断依据和处理记录。共享额度、重复消息检查与等待在不同通道、设备间仍生效，不会因另建任务而消失。
