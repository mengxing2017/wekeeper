# 官方发送账号

入口：企业微信分发管理 → 发送账号。这里管理官方成员的发送基础资格，与手机登录账号无关。

## 从哪里获得身份

1. 平台维护人员在企业微信集成中同步成员，在客户群总览中同步官方群目录。
2. 在登录账号管理中，按已有身份规则建立已核实官方成员与平台账号的映射。
3. 在学校成员与权限中，为该账号配置实际学校运营或管理员资格。
4. 在发送账号页查看成员验证、启用状态和学校基础资格。没有可靠映射时不会按姓名自动生成身份。

学校人员只看到本校摘要。平台维护人员可以查看全平台学校资格并停用；停用会阻止后续任务调用，不改写历史结果。
“基础条件满足”不是本次发送许可。官方群、目录时效、凭据代际、人工确认及资源限制仍在每次任务中校验。
平台管理员身份不自动代替学校确认权限。直接文本任务仍由本校管理员确认。

## 历史入口

原 execution-accounts 及设备 accounts 书签会显示迁移说明：选择官方发送账号，或前往历史手机人工登记资料。
旧资料只读保留，不认证手机实际登录身份，不转换为官方成员，不赋予官方发送资格。

## 资源治理

平台视图下可调整内置来源的积压限制及暂停状态。积压限制分别约束草稿数量和待执行批次数，不是保证发送次数。
官方资源限制使用 `wecom:企业ID:官方成员userid小写` 键；服务端验证该资源确实存在。
每个窗口的调用用量跨来源、跨学校累计。窗口值由运营确定，不宣称是官方安全发送额度。
修改政策会使旧预览失效，应重新预览；停止和结果核对不因来源暂停而被关闭。
手机共享发送有独立的能力及业务范围办理，这些官方账号配置不会启用手机发送。
