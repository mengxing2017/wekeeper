# 调用方凭据与路由授权

WeKeeper 是上游接收服务，Linjian 是下游调用方。所有请求均由 Linjian 主动发起：提交消息、检查凭据和路由、查询回执。WeKeeper 不回调下游，不探测或查询 Linjian 在线状态。

Docker 部署使用本功能前，由部署人员按 [Docker 主密钥配置说明](../../runbooks/docker.md#调用方凭据主密钥-首次配置与已有部署更新)设置并保存 `WEKEEPER_SOURCE_MASTER_KEY_V1`；它仅供 WeKeeper 内部加密存储，不交给下游。`make dev-embedded` 会为本次临时数据库自动配置；Docker 不会自动生成。

“消息接收管理 → 调用方凭据”属于消息接收业务，目前由系统管理员维护，不依赖企业微信或移动端工作空间。

在“调用方凭据”新增记录，填写单位名称、凭据备注、状态和有效期。每个下游对应一条调用方凭据，保存时生成唯一的凭据 ID（key_id）和签名密钥（secret）；无需另外创建平台，也不配置下游地址、可信网址或内容路径前缀。WeKeeper 不保存学校目录。

下游只需填写以下三项，凭据 ID 可直接复制：

| 页面字段 | 下游配置字段 | 用途与获取方式 |
| --- | --- | --- |
| 凭据 ID | `key_id` | 同时标识调用方与其凭据，放入签名请求头 `X-Source-Key-Id`；不是签名密钥 |
| 签名密钥 | `secret` | 用于请求签名，与 `key_id` 配套；在凭据详情点击“查看密钥”查看、复制或下载，可重复核对 |
| WeKeeper 服务地址 | `origin` | 本次部署对下游公开的 WeKeeper HTTPS 地址，由部署人员提供 |

给下游的凭据是 **`key_id` 与 `secret` 这一对**，无需额外填写调用方 ID。路由的 `route_id` 在凭据子项中选择，用于消息分发，不代替签名凭据。WeKeeper 存储主密钥 `WEKEEPER_SOURCE_MASTER_KEY_V1` 仅供内部使用，不交付给下游。

左侧“消息接收管理”分组提供“调用方凭据”入口。新增凭据后，在该凭据行打开“消息分发路由”子项，填写路由名称、备注和状态；调用方归属自动带入，无需另行选择或填写 ID。route_id 由服务端生成且保持不变，新建路由后自动授权给当前凭据。若创建成功但授权失败，路由仍显示在列表中，可点击“授权”重试，不必重复新增。

子项只列当前调用方的路由，支持搜索、状态筛选和分页。可编辑路由名称、备注和启停状态，也可对当前凭据授权或撤销授权；关联双方必须属于同一调用方。凭据签发后与对应下游绑定，不提供轮换功能。

列表支持标识或名称、凭据 ID、状态及失效时间上界筛选。详情区分凭据备注与各路由备注。创建后打开“详情 / 编辑”，在“下游连接配置 → 签名密钥（secret）”点击“查看密钥”，可查看、复制密钥或下载包含 key_id、secret 的凭据文件，再交给下游填写。可隐藏并反复查看同一份 secret，已通过后台命令交付的凭据也可查看；查看不会重新签发或更换密钥。关闭详情后隐藏密钥，每次查看记录操作人、凭据及请求审计，审计不保存密钥值。Linjian 管理员另行填写部署人员提供的 WeKeeper HTTPS 地址。

凭据编辑可以修改单位名称、备注、状态和有效期，不能转移调用方归属。路由授权在凭据的“消息分发路由”子项中维护，不再手工粘贴路由 ID。修改版本冲突时刷新后核对；撤销授权只取消关联；删除凭据则永久删除整条凭据、其关联路由和路由授权，保留历史收件、任务和审计。

有效期支持“长期有效”和指定失效时间。新增默认长期有效，仍须满足生效时间与启用状态；可随时改为指定失效时间。长期有效在接口中使用 `valid_until: null`，不使用远期日期代替。

删除凭据需确认，凭据及其消息分发路由不可恢复，既有历史收件、任务和审计保留；旧 key 随即失效。升级迁移会清理此前已软删除的凭据及其路由。内容链接只作为消息内容保存，按 HTTPS 链接格式校验，不抓取、不回调，也不要求登记可信域名。正常消息不需要逐条调用认证或办理人工审批。收件只代表持久受理，发送结果以实际回执为准；配置并启用自动执行后，WeKeeper 会创建对应通道任务；收件、创建任务和真实发送是不同阶段。

## 单位、分组与路由执行配置

系统管理员从“消息接收管理 → 业务单位与分组”维护目录，从“消息接收管理 → 路由执行配置”直接选择路由并配置自动执行。也可在凭据的消息分发路由行打开“执行配置”。获授权的工作空间管理员使用“路由执行配置”入口，只看到其获授权且具备对应工作空间管理权限的路由；“调用方凭据”和目录管理仅系统管理员可见。选择单位、分组、一个发送通道、对应工作空间和明确的目标群。分组目录用于组织资源，新增目录目标不会自动扩大已有路由。群只填写一个业务名称。

保存只生成完整配置修订，不自动启用。检查通过后，点击启用并确认自动执行授权：后续合法来源消息无需逐条确认，系统按该路由为每条内容冻结正文、目标及手机授权候选；业务额度和单次执行许可仍然生效。手机离线或本地适配缺失不影响收件和任务受理。手动创建的发送任务继续使用原人工确认流程。

暂停会继续收件，暂停新任务及尚可控制的提交；恢复后持久积压自动重试，不要求来源重发。配置暂缺有效目标、授权手机或企业微信发送账号时显示具体检查原因，修复后继续。已交付的手机包或已提交的官方请求无法撤销，结果仍按原任务入账。退役不可恢复，也不能复用路由标识。删除凭据立即停止该凭据的新请求，但保留已授权任务、回执及审计。

系统管理员可按账号授予明确的路由管理权限。获授权的工作空间管理员只看到其可配置路由，还须拥有所选通道工作空间管理权限；不能查看调用方 secret 或修改接入授权。配置冲突时保留本地编辑并展示最新修订，核对后再加载或保存。历史与交付信息用于追踪，不作为业务放行门槛。
