# 调用方凭据与路由授权

WeKeeper 是上游接收服务，Linjian 是下游调用方。所有请求均由 Linjian 主动发起：提交消息、检查凭据和路由、查询回执。WeKeeper 不回调下游，不探测或查询 Linjian 在线状态。

Docker 部署使用本功能前，由部署人员按 [Docker 主密钥配置说明](../../runbooks/docker.md#调用方凭据主密钥-首次配置与已有部署更新)设置并保存 `WEKEEPER_SOURCE_MASTER_KEY_V1`；它仅供 WeKeeper 内部加密存储，不交给下游。`make dev-embedded` 会为本次临时数据库自动配置；Docker 不会自动生成。

“消息接收管理 → 调用方凭据”属于消息接收业务，目前由系统管理员维护，不依赖企业微信或移动端工作空间。

在“调用方凭据”新增记录，填写单位名称、凭据备注、状态和有效期。每个下游对应一条调用方凭据，保存时生成唯一的凭据 ID（key_id）和签名密钥（secret）；无需另外创建平台，也不配置下游地址、可信网址或内容路径前缀。WeKeeper 不保存学校目录。

下游只需填写以下三项，凭据 ID 可直接复制：

| 页面字段 | 下游配置字段 | 用途与获取方式 |
| --- | --- | --- |
| 凭据 ID | `key_id` | 同时标识调用方与其凭据，放入签名请求头 `X-Source-Key-Id`；不是签名密钥 |
| 签名密钥 | `secret` | 用于请求签名，与 `key_id` 配套；在凭据详情点击“查看密钥”查看、复制或下载，可重复核对 |
| WeKeeper 服务地址 | `origin` | 本次部署对下游公开的 WeKeeper HTTPS 地址，由部署人员提供 |

给下游的凭据是 **`key_id` 与 `secret` 这一对**，无需额外填写调用方 ID。路由的 `route_id` 在凭据子项中选择，用于消息分发，不代替签名凭据。WeKeeper 存储主密钥 `WEKEEPER_SOURCE_MASTER_KEY_V1` 仅供内部使用，不交付给下游。

左侧“消息接收管理”分组提供“调用方凭据”入口。新增凭据后，在该凭据行打开“消息分发路由”子项，填写路由名称、备注和状态；调用方归属自动带入，无需另行选择或填写 ID。route_id 由服务端生成且保持不变，新建路由后自动授权给当前凭据。若创建成功但授权失败，路由仍显示在列表中，可点击“授权”重试，不必重复新增。

子项只列当前调用方的路由，支持搜索、状态筛选和分页。可编辑路由名称、备注和启停状态，也可对当前凭据授权或撤销授权；关联双方必须属于同一调用方。凭据签发后与对应下游绑定，不提供轮换功能。

列表支持标识或名称、凭据 ID、状态及失效时间上界筛选。详情区分凭据备注与各路由备注。创建后打开“详情 / 编辑”，在“下游连接配置 → 签名密钥（secret）”点击“查看密钥”，可查看、复制密钥或下载包含 key_id、secret 的凭据文件，再交给下游填写。可隐藏并反复查看同一份 secret，已通过后台命令交付的凭据也可查看；查看不会重新签发或更换密钥。关闭详情后隐藏密钥，每次查看记录操作人、凭据及请求审计，审计不保存密钥值。Linjian 管理员另行填写部署人员提供的 WeKeeper HTTPS 地址。

凭据编辑可以修改单位名称、备注、状态和有效期，不能转移调用方归属。路由授权在凭据的“消息分发路由”子项中维护，不再手工粘贴路由 ID。修改版本冲突时刷新后核对；撤销授权只取消关联；删除凭据则永久删除整条凭据、其关联路由和路由授权，保留历史收件、任务和审计。

有效期支持“长期有效”和指定失效时间。新增默认长期有效，仍须满足生效时间与启用状态；可随时改为指定失效时间。长期有效在接口中使用 `valid_until: null`，不使用远期日期代替。

删除凭据需确认，凭据及其消息分发路由不可恢复，既有历史收件、任务和审计保留；旧 key 随即失效。升级迁移会清理此前已软删除的凭据及其路由。内容链接只作为消息内容保存，按 HTTPS 链接格式校验，不抓取、不回调，也不要求登记可信域名。正常消息不需要逐条调用认证或办理人工审批。收件只代表持久受理，发送结果以实际回执为准；配置并启用自动执行后，WeKeeper 会创建对应通道任务；收件、创建任务和真实发送是不同阶段。

## 单位、分组与路由执行配置

系统管理员从“消息接收管理 → 业务单位与分组”维护目录，从“消息接收管理 → 路由执行配置”直接选择路由并配置自动执行。也可在凭据的消息分发路由行打开“执行配置”。获授权的工作空间管理员使用“路由执行配置”入口，只看到其获授权且具备对应工作空间管理权限的路由；“调用方凭据”和目录管理仅系统管理员可见。选择单位、分组、一个发送通道、对应工作空间和明确的目标群。分组目录用于组织资源，新增目录目标不会自动扩大已有路由。群只填写一个业务名称。

保存只生成完整配置修订，不自动启用。检查通过后，点击启用并确认自动执行授权：后续合法来源消息无需逐条确认，系统按该路由为每条内容冻结正文、目标及手机授权候选；业务额度和单次执行许可仍然生效。手机离线或本地适配缺失不影响收件和任务受理。手动创建的发送任务继续使用原人工确认流程。

暂停会继续收件，暂停新任务及尚可控制的提交；恢复后持久积压自动重试，不要求来源重发。配置暂缺有效目标、授权手机或企业微信发送账号时显示具体检查原因，修复后继续。已交付的手机包或已提交的官方请求无法撤销，结果仍按原任务入账。退役不可恢复，也不能复用路由标识。删除凭据立即停止该凭据的新请求，但保留已授权任务、回执及审计。

系统管理员可按账号授予明确的路由管理权限。获授权的工作空间管理员只看到其可配置路由，还须拥有所选通道工作空间管理权限；不能查看调用方 secret 或修改接入授权。配置冲突时保留本地编辑并展示最新修订，核对后再加载或保存。历史与交付信息用于追踪，不作为业务放行门槛。

## 收件与回执

从左侧“消息接收管理 → 收件与回执”直接进入，选择路由行的“查看收件与回执”。也可在凭据的消息分发路由行，或“路由执行配置”的路由行，点击“收件与回执”。列表限定当前路由，显示事件、内容、版本序号、素材状态、处理阶段、原因和发送摘要。点击“查看回执”可查看处理时间线、检查记录和版本关联；页面会定期刷新。

“素材已应用”表示共用检查通过；“等待执行配置”表示平台已受理、配置修复后继续。“任务已创建”仍不等于已发群，发送摘要按目标统计待处理、已发送、失败、结果未知，手机换机不增加目标数。撤回只停止尚可控制的执行，已交付或已提交的尝试继续按实际结果入账，结果未知之后也可能收到迟到成功。

同序号等价事件不重复创建任务；同序号不同正文显示内容冲突；低版本不能覆盖当前版本。更新前已有签包、提交、发送或不确定事实时，更新素材默认不再次群发，历史任务结果保留在原回执中。

系统管理员可对当前版本因原文或最终正文关键字检查拦截的内容填写原因并“按当前规则重检”。给路由配置管理员授权时，可独立勾选“允许重检收件”；运营人员还须保有对应工作空间管理权限。重检保留原回执、原文和拒绝历史，不能强制放行；过期版本、撤回版本和内容冲突不能通过重检重新获得发送资格。权限撤销或处理修订变化会由后端重新校验。

调用方查询机器回执时，retryable=false 表示不需要重发原请求，仍可持续查询发送进展。按服务端建议的轮询间隔查询，遇到限流或暂时不可用按 Retry-After 退避；不要按成功受理次数累计实际发送数量。


## 关键字规则

从左侧“消息接收管理 → 关键字规则”直接进入。系统管理员可维护全局、调用方、业务单位、路由及两类工作空间的规则；工作空间管理员只看到自己当前可管理的工作空间附加规则。各适用范围叠加生效，本地删除或停用词条不能取消上游限制。

在范围行点击“查看与发布”，查看版本历史与条目；选择“编辑当前规则”后添加、移除或启停关键字，填写发布原因并发布。空集合也须明确发布。版本冲突表示其他人已发布，请保留并核对本地输入、重新加载当前版本后再修改。每范围最多 2000 条，相同规范化结果不能重复；词条原始长度最多 512 字节，规范化结果最多 128 个 Unicode 标量。

匹配统一使用 Unicode 18.0.0 的兼容规范化与完整大小写折叠；全角、大小写及 Straße/STRASSE 等等价写法会命中。不会合并连续空格、换行，也不会删除零宽字符。页面历史条目展示服务端规范化文本。原文和最终发送正文均不因检查被删改或打码。

发布立即影响新的签包和官方提交资格，后台重检进度在范围列表显示。受影响内容自动重检，存储故障保留重试，不必来源重发。规则放宽后沿用原任务恢复尚可控制的目标，不重复创建任务或重发已成功目标。已交付手机包和已提交请求继续执行，结果未知及迟到结果仍按原尝试核对。

在“收件与回执”的详情中查看“关键字检查证据”，分别展示原文公共范围、原文工作空间及最终正文检查。选择“查看证据”可查适用范围及版本、输入摘要、完整命中规则分页和位置样例。位置指向规范化文本的 Unicode 标量区间，左闭右开；样例最多 100 条，截断不代表其他命中规则被忽略。最后正文包含真实链接和换行，因此原文通过后仍可能在最终检查被拦截。

有明确重检权限的人员可以填写原因请求重检；这只按当前规则重新计算，不能强制通过。正常无广告消息可直接处理，不需要等待广告配置或研发验收。

## 广告素材与共享

从左侧“消息接收管理 → 广告素材与共享”进入。系统管理员可在“业务单位与分组”的单位行或广告页面授予现有登录账号“编辑素材”和“管理共享”两项独立能力。单位广告管理人员不需要加入发送工作空间；此项权限不会授予收件正文或发送任务查询权限。

新建广告时选择所属单位、填写名称与纯文本正文，可附一个 HTTPS 链接。所属单位创建后不能改变。初始投放范围只包含本单位明确选择的通道工作空间；不选工作空间则暂不可投放，不会默认共享给其他单位。正文与链接发布为不可变版本，修改不会改动已有任务的冻结正文。

有共享管理权限时，在广告详情的“投放授权与禁投”中选择单位、分组或路由及通道工作空间，填写有效期、发布原因后发布。禁投优先，未明确授权的范围不能选用。接收方只可查看与投放，不能修改素材、扩展共享或转移所有权。发布冲突时保留输入，核对服务器最新修订后再加载或编辑。

共享不会自动插入广告。从左侧“消息接收管理 → 广告序列轮询”进入，选择路由行的“配置广告序列轮询”；广告素材页也提供“配置广告自动序列轮询”跳转入口。页面只列出当前账号有权管理的路由，在其中主动选择“不插广告”“固定广告”或“序列广告池”。原有“路由执行配置”抽屉和调用方凭据的路由行仍可打开广告配置。固定广告可选前置/后置、广告不可用时无广告回退或等待修复，并决定是否允许全未执行任务自动恢复。保存配置只影响新消息，旧任务继续使用原选用配置。

在配置下方输入来源标题、正文和链接，点击“预览组合（不创建任务）”查看实际正文、长度、原文与最终关键字检查。广告名称不会插入消息。原文被拦截时不会选择广告；广告组合被最终规则拦截时，按已选策略回退或等待修复。广告正文过长不会截断或拆成多条消息。

“收件与回执”的详情展示广告决策与组合快照，包括排除原因、正文、广告内容/策略版本、检查引用、共享正文快照和替代关系。广告停用、撤权或到期立即阻止尚未签包/提交的目标；后台自动重检。仅当整个业务意图的所有历史尝试均未开始，且原配置允许恢复时，才会换代使用合格正文或无广告回退。出现签包、官方可能提交、成功或结果未知后保持原正文，已交付手机包继续本地执行，迟到结果按原尝试归账。

“有序广告池”按显示顺序循环，重复添加同一广告会得到独立槽位。例如 A1、A2、A2、A1 会严格重复该排列，末尾和下一轮开头可以连续选择 A1。先添加槽位、上下移动或删除，填写原因并“发布序列”，再保存广告模式为“序列广告池”。空池或全部广告不可用时，按无广告回退或等待修复配置处理，不占广告轮次。

发布序列保留池的身份：最后选用槽位仍存在时，从它的新位置的下一槽继续；被删除时从新首槽继续。“从首槽重置（仅新决策）”要求填写原因并核对最新进度，重置只影响之后创建任务的新决策，不修改既有任务。发布或重置发生版本冲突时保留输入，请先核对服务器最新进度。复制已发布规则只允许选择尚未创建广告池的其他授权路由，目标建立新池和新槽位，从头开始，两个路由不共享进度。

预览显示当时的规则、游标、扫描排除原因与正文，不占轮次；并发处理下实际选用可能变化。消费记录中的选用序和轮次用于核对序列，选用次数是任务创建时的槽位消费次数，不能当作曝光、送达或计费数量。实际目标的送达、失败、不确定和进行中分别统计。

序列池任务创建后，广告、槽位、版本和正文保持冻结。发送失败、部分群失败、unknown、手机换机或广告配置修复都不会再次消费或替换广告；已创建的无广告回退任务也不会事后补选广告。广告停用或撤权仍保护尚未提交的目标，修复后只检查原冻结内容是否可继续，已交付手机包继续本地执行。

广告页面顶部提供“新增广告”。系统管理员尚未创建可用单位时，按钮保留并提示先到“业务单位与分组”创建或启用单位；只有共享选用权限的账号需由系统管理员授予单位广告编辑权限。

在广告列表行或详情中点击“删除广告”，填写删除原因并确认。删除使用归档机制，停止提供选用并触发已有任务的失效检查，历史正文、版本、发送结果与审计继续保留；普通列表移除该广告，可通过“已删除广告”筛选回看。共享接收方没有删除权限。

## 自动链路任务

从“消息接收管理 → 自动链路任务”进入列表，按来源、单位、路由、状态或时间查看当前授权工作空间内的进度。收件与回执、路由行也提供任务入口。企业微信“群发任务”和移动端“手机任务”页顶部的“自动链路执行与证据”可按当前通道、工作空间进入列表；可切换执行通道或查看全部授权工作空间。收件成功不代表送达，任务全部目标成功才显示全部成功。

详情提供冻结正文、路由修订、广告与规则依据、阶段轨迹、每群结果及历史尝试。任务执行期间正文只读，不需要逐条确认。普通运营可查看本工作空间任务；系统管理员或对应工作空间管理员可停止后续可控执行，或推进仍在预算内的可恢复目标。停止不撤销已经发送的事实，也不能收回手机已接收的执行包；迟到结果继续入账。配置修复不会复活已停止任务。

手机接收后五分钟没有最终结果会按原授权候选范围换机，可能出现跨手机重复；企业微信结果不确定时保留外部证据并核对，不直接重发。推进可恢复目标不会重发成功群，不重置手机轮次、截止时间或授权范围。

路由执行配置中的“版本投递策略”默认更新未提交引用而不重复群发。管理员可以明确授权启用后续新版本再投；策略只对生效后的合格更高版本有效，旧版本存在未核清的可能提交证据时不建立版本再投。变更策略不会回溯发送已经处理的历史素材。

列表每行的“执行证据”直接打开详情中的同名页签；“任务详情”打开任务概览。执行证据区分平台受理、官方创建、微信侧成员执行、官方逐群结果和设备反馈，并保留观察时间及原尝试身份。企业微信成员在微信侧确认属于外部通道流程，无需回平台逐条确认；设备反馈成功不等于官方验证送达。
