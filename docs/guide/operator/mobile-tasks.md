# 手机发送任务

适合有当前学校发送权限的管理员及配合准备内容的运营。入口：“企业微信 → 手机发送任务”。需确认提交的操作由有相应学校权限的人员完成。

## 开始前

由平台管理员[登记手机和发送账号](../platform-admin/devices-and-accounts.md)，学校管理员[分配流程并启用学校执行](../school-admin/delivery-setup.md)。当前新任务使用企业微信群纯文本通用流程 v5。离线手机可排队，但实际执行要求匹配的手机端、有效授权和权限，以及已真实验证发布的流程。

## 后台三步操作

1. 打开“配置消息”，在“选择范围”选择已分配流程的执行手机与账号。核对手机和账号显示，不要只凭设备名称猜测身份。
2. 点击“填写消息”，填“批次名称”“发送正文”“群间等待秒数”。例如批次名可填“示例学校周一通知”，正文先在隔离测试群验证。不能把生产群用于学习测试。
3. 为每个执行者选择有序群，用“上移”“移除”调整顺序。同一批次的一个群只能分给一个执行者。
4. 查看完整预览，逐项核对学校、手机、账号、正文、群和等待间隔，再人工确认。间隔只能满足或延长当前政策下限，不能为赶进度缩短。
5. 在“批次进度”打开该批次，查看每台手机、当前群、任务结果和失败原因。

## 手机上操作

使用独立执行端配对，核对服务地址、账号和学校并明确接受 v5 业务授权；打开必要的通知和无障碍权限，按执行端要求保持手机解锁。业务人员不需要编辑 JSON 或采集页面规则；需要适配时交给平台维护人员。

手机收到任务、队列排队和实际发出消息是三个状态。页面显示“待升级后执行”时，请负责人升级匹配执行端；不要重复建任务。

## 异常处理

离线先恢复连接；暂停后在原批次确认条件再恢复。停止不撤回已发消息。结果不确定时先人工核对，不能用换批次、设备或通道规避。更换流程后仅对确定未发送的剩余群重新预览确认，见[结果与异常处理](results-and-recovery.md)。

完成后，应能从原批次找到逐群结果和证据；真实企业微信页面适配需另做真机验收，后台可保存任务不等于已经支持所有应用版本。
