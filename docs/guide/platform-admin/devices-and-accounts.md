# 手机接入与资源约束

手机是系统共享资源，可服务多个任务，系统管理员统一管理目标、任务和消息。

登记手机并生成配对码，现场人员在 keeper-otter 完成配对。手机端自行管理本机意愿、系统权限与后台连接，平台只观察认证连接与具体执行结果。

系统管理员在单位接收配置或手动任务确认群和候选手机，不另办范围开通。单位方案和默认规则见[手机业务方案与资源约束](shared-mobile-resources.md)。

手机离线与具体尝试结果分别展示。研发交付、发行激活及验收不属于业务办理步骤。unknown 核对和原结果补报保留，不通过重新配对跳过未决结果。

## 设备在线与连接恢复

设备常态每 60 秒维护一次心跳。平台收到有效设备心跳并回复，或收到平台探测对应的设备响应，即立即确认在线。每次成功心跳交互都会更新最新心跳时间，下一次主动心跳从该时间起等待 60 秒；命令回执不计作心跳。系统只保留最新心跳状态，不累计心跳历史。单次回包超时、网络切换或控制连接重建只表示通道需要恢复，不会立即判设备离线。

默认最后一次有效心跳后连续 3 个周期及 10 秒响应宽限均无有效通信，即 190 秒后，才判超时离线。130 秒后可能显示“连接不稳定”，此时尚未离线，不因该提示触发离线换机。设备停用、凭据失效和执行暂停单独显示；设备在线不代表已具备发送条件。页面“状态待刷新”表示页面未取得新快照，不代表设备离线。

平台不查询、存储、展示或改变本机托管意愿。平台业务执行开关、使用范围暂停/撤销与设备停用只约束平台业务；指定执行取消只作用于对应 execution ID。
