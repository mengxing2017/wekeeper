# 手机设备与发送账号

适合平台管理员和配合核对手机身份的负责人。入口：“平台管理 → 手机设备与发送账号”。手机端为独立 keeper-otter 项目，需使用与服务端匹配的版本。

## 按顺序准备

1. 登记手机，使用手机端显示的有效短码完成配对；保留开头的 0，并核对设备名称。
2. 核对设备启用状态和实际执行端接入状态。配对成功不等于手机已获业务授权或已具备真实应用适配能力。
3. 登记或选择真实发送账号，先查看候选与资格；在这台手机上核对实际登录的企业、账号名称等界面资料，再完成明确确认。
4. 将账号与学校及设备关联，核对群的完整可见名称、群类型及辅助资料。同名群需要额外核对，不能凭内部系统标识定位手机页面。
5. 交学校管理员在“手机发送任务 → 执行设备与账号”分配已发布流程。

## 手机上操作

核对服务地址与配对结果，在手机明确接受对应学校、账号和用途的业务授权，打开必要权限。授权撤销与本机暂停不同：暂停不一定停止收件，撤销授权则影响新计划接收。维护工具和业务执行端职责不同，不要求普通业务手机做规则采样。

## 结果与故障

完成后应能看见正确设备、账号和接入状态，学校能够选到合法分配。短码过期重新生成，不猜测他人短码。账号核对被拒绝时看具体资格提示，不反复切换账号绕过。设备离线先检查网络与应用状态，不为同一消息重建任务。
