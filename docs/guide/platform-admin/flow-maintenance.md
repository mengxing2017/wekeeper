# 流程维护与发布

适合承担真实应用适配的维护人员，不是业务人员每日必做事项。入口为“手机设备与发送账号”中的规则与政策维护区域。开始前准备有学校管理权限的试验范围、维护版执行端和隔离测试群。

## 维护步骤

1. 在“发起真实 v5 维护验证”选择维护设备和验证类型。首次没有流程时，填写真实应用名称和包身份，发起人工计时，并在手机明确接受。
2. 由人工真实操作生成成功计时样本，在“复用真实人工基准”选择样本建立保守基准。不能编造样本数，也不能用自动执行时间代替人工样本。
3. “新建或复制流程”，通过可视化表单维护完整页面、角色、导航与桌面路径。不要让业务人员编辑 JSON、固定坐标或控件 ID。
4. 发起完整页面角色核验及每条非空桌面路径的测试打开；专项分支也需要验证。维护手机明确接受后完成真实验证。
5. 在“验证发布”选择版本与成功验证证据，发布到明确学校；再由学校管理员分配到设备账号。
6. 从“执行失败归并”查看稳定失败原因，修正后生成新版本并重新验证发布。

## 完成后应该看到什么

学校能选择到已发布流程及对应证据。已有任务保持原确认内容；新发布不会偷偷改写在途任务。没有真实成功证据时，不提供可执行的示例默认规则，也不能把合成测试结果当作上线证据。

## 故障与交接

锁屏、权限不足和网络等待先处理环境条件；账号/群歧义、正文改变或可能已发不能降级重试。暂停批次要改用新流程时，只重建确定未发的剩余项，见[结果处理](../operator/results-and-recovery.md)。
