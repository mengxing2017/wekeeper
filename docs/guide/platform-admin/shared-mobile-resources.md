# 共享手机与目标群

学校拥有自己的手机目标群及任务，手机属于平台共享资源池。一台手机可绑定多所学校的群，一个群也可绑定多台候选手机；一次投递仍只能由一台手机执行。

学校管理员先维护目标群，再联系平台资源维护人员。在“平台功能 → 共享手机与目标群”选择学校目标群及共享手机，核实后建立绑定。学校只能查看本校绑定，不能自行取得全局设备权限，不需要维护学校设备授权名单。

下发群名是手机搜索文字。不同手机使用不同群备注时，在对应绑定填写“该手机下发群名”；留空继承群默认名。只修改默认名不会影响使用独立覆盖名的绑定。绑定不证明实际群成员身份，现场仍须核实视觉顺序第一个群结果。

停用某一绑定只影响该手机与该群，不停用手机、不影响其他学校。迁移前的绑定默认停用，须人工核实后重新启用，不通过学校授权、责任人或同名群推断关系。

共享执行升级期间，旧学校设备执行配置和任务确认停止受理；已有任务和证据保留，只有尚未领取任务可以普通取消。共享调度与新版手机协议全部验收后再开放实际发送。

## 设备全局能力与手机同意

新版设备全局能力不携带学校授权关系。当前后端提供平台资源管理员专用的 `device-capabilities` 查询、创建和版本化更新接口，以及手机凭据专用的 v7 `capability-context` 和 `capability-consents` 接口。配置必须显式采用 v7 流程；不自动转换旧学校流程或同意。配置版本保存不可变快照，修改或启停后旧同意不再作为当前配置同意。

手机在能力页刷新配置，核对平台、设备、应用、能力、配置版本与摘要后，通过 Android 原生弹窗接受或撤销。同意记录绑定本机凭据代次；换代需要重新确认。请求结果不明时补报原始请求，本机阻止不会因刷新或迟到回执自动解除。

平台 Web 在“共享手机与目标群 → 设备能力配置”维护全局配置：选择共享手机、填写名称、导入维护人员针对真实应用界面核对的 v7 JSON 流程文件，核对应用和安装包后发布。新增配置默认停用；修改或启停均生成新版本，须手机重新确认。完整规则与执行预算由后端校验，文件不能超过 256 KiB。不提供旧协议转换或示例规则自动填充，也不要使用旧学校执行配置入口。

发布请求失败时可重试同一发布请求，页面保留原始内容、版本和幂等键；如需处理校验错误或版本冲突，关闭后重新载入列表核对，不能凭错误提示认定发布未成功。当前列表展示配置状态、版本和摘要，尚未接入服务端同意回执查询，也不能获知手机本地阻止状态，需在手机端核对当前同意。本批所有能力回执均不构成发送资格；全局现场验证、设备租约、任务许可和真实设备验收完成前，实际发送继续关闭。
